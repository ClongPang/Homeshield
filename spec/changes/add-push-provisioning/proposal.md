# 提案：联防者推送通道自助开通（插件关注前置 + OAuth 一键映射 + 手机号入录 + 送达确认闭环）

## Why

高危告警的无窗口触达腿（应用消息 → 微信插件）是联防者提醒的命脉，但其开通目前是三段分属两个世界的散落操作：

- **管理员在企微后台**把联防者加入通讯录（corp_userid 存在的前提，一次性）；
- **管理员在服务器**查到应用内部的 `user_id` 与对方的 corp_userid，敲 `homeshield wecom-link --user-id N --corp-userid X` 完成映射——`user_id` 是内部 ID，管理员不可见，极易错绑；
- **用户自行**找管理员要二维码、扫码关注微信插件，系统内没有任何引导。

三段之间没有状态呈现：绑没绑、能不能收到，只能"发了条消息试试看"。映射缺位时告警静默降级为客服会话 48h 回落，高危预警的时效优势形同虚设；而绑定动作本身（命令行 + 内部 ID）对一个面向家庭的产品完全不可接受。

**目标**：把「绑定 → 关注插件 → 送达确认」收敛为联防者在自己的微信里自助完成的单一"开通推送"流程，管理员从每用户三步操作退到一次性配置。对齐产品哲学：机制而非场景——产品只提供"开通"机制，是否开通是联防者自己的选择；送达状态如实呈现，不再只能猜测。

**边界（不变的前提）**：corp_userid 只存在于企微通讯录侧，客服会话回调只有 external_userid，绑定必须由用户在企微侧"证明自己"，这一前提无法消除、本提案只把它做到近乎无感。运营主体为个人，企业微信必然处于**未验证状态**：通讯录同步、微信插件、可信域名/可信 IP 等机制的可用性以未验证企业实际可用者为准，全部纳入前置验证（交接约定 #4），不可用面按降级规则处理、不假设验证企业权限。查询者（被联防者）零变化，始终不需要任何企微概念。

## What Changes

以一条四态状态机组织：**未绑定 → 已绑定（未确认）→ 送达就绪**，外加**异常**态（发送同步报错或确认超时）。

- **统一入口与绑定凭证**：开通入口统一为客服会话/控制台下发的带 token 链接（复用现有 `_send_console_link` 与 alert 链接的凭证模式）；开通页据此确定内部 `user_id`，以一次性、短 TTL（默认 10 分钟）的 OAuth state 承载该映射，无凭证或过期 state 一律拒绝绑定。
- **插件关注前置（第一屏）**：开通页首屏即呈现插件邀请二维码（客服会话图片消息优先、控制台兜底展示同一二维码），用户扫码关注插件——这是无窗口触达的物理前提（43004："未关注微信插件"），也是 OAuth 微信端成员识别的依据，对所有人无条件先行，不再作为绑定成功后的跟进步骤。
- **OAuth 身份映射（主映射）**：关注后用户在开通页触发企微网页授权（snsapi_base 静默）→ 回调 code 换成员 userid → 自动绑定。已入录且已关注者全程零输入；授权返回非成员身份（未入录，或微信端行为与预期不符）时自动转入手机号分支——用户不需要先知道"我在不在企业里"。
- **手机号自助绑定/入录（辅映射）**：用户提交本人手机号，`user/getuserid` 命中即绑定；未命中且开启自助入录时经 `user/create` 创建成员并绑定（开关默认关），未开启时呈现引导文案。
- **送达确认闭环（单信号）**：绑定后发一条含确认链接的测试应用消息，用户确认 → 通道就绪；发送 API 同步报错（如 43004）或超时未确认 → 转异常态并在控制台呈现原因、提示重测。官方应用消息**没有投递失败回调**（errcode=0 仅代表提交成功，超频还会静默丢弃，见机制表），故不订阅、不依赖任何"发送失败事件"；日后官方补齐该事件可叠加为增强，不作为本提案承诺。
- **控制台状态与解绑**：设置区状态灯（未绑定 / 已绑定未确认 / 送达就绪 / 异常）+ 各态下一步入口 + 关闭推送（解绑）。
- **CLI `wecom-link` 退役**：`WecomMemberRepo.link` 保留为自助流程的内部落库 API；既有映射迁移标记来源 `cli`。

### 已定设计决策（实施阶段不再讨论）

| 决策点 | 选择 | 理由 |
|---|---|---|
| 流程次序 | 插件关注（扫码）前置为第一屏，OAuth 静默授权为身份映射收尾 | 应用消息触达本身就要求关注插件（43004），OAuth 微信端成员识别亦基于该关注关系；关注先行后，无论"微信端 OAuth 对关注者返回 userid"（验证②）结果如何，流程都成立 |
| 绑定条件 | 仅当授权返回成员 userid | 非成员返回 openid/external_userid，一律不绑定——堵住"绑别人的 corp_userid 收他人家人提醒"的隐私口子 |
| 授权 state | 一次性、短 TTL（默认 10 分钟）绑定凭证，承载 user_id 映射 | 入口凭证统一走带 token 链接；state 防重放绑定 |
| 手机号探测 | 仅用户自报触发 + 失败计数护栏 | 官方约定：错误次数超企业人数上限 20% 将 1 天不可调用，不可批量扫 |
| 纯手机号直绑 | 不作为独立承诺路径 | 手机号是半公开信息，证明不了"你就是你"；手机号只作入录凭证，绑定仍以 OAuth 收尾（扫码→入录→点链接）。可信域名未就绪的过渡期允许手机号直绑 + 测试消息确认 + 一键解绑作为降级 |
| 自助入录 | 开关化（默认关） | `user/create` 仅通讯录同步助手可调，通讯录写权限属企业级信任决策，由运营者显式开启；未验证企业下通讯录同步助手可用性存疑，以交接约定 #4 核验为准，不可用则该路径整体隐藏 |
| 二维码下发 | 绑定流程第一屏下发（关注前置），绑定后不重复下发；客服会话图片优先、控制台兜底 | 用户本来就在微信聊天里，摩擦最低；kf send_msg 支持 image（先传临时素材） |
| 送达判定 | 测试消息+用户确认 单信号；发送同步报错与确认超时为异常入口 | 官方接收事件文档查无应用消息投递失败回调（已核验不存在，见机制表）；errcode=0 仅代表提交成功且超频静默丢弃——"返回成功不代表最终送达"仍成立，闭环只能靠用户确认 |

### 已核验机制（官方文档逐条钉死，实施可直接引用）

| 机制 | 结论 | 出处（开发者中心文档路径） |
|---|---|---|
| 授权链接 | `open.weixin.qq.com/connect/oauth2/authorize?appid=CORPID&redirect_uri=…&scope=snsapi_base#wechat_redirect`；snsapi_base 静默授权返回 UserId；agentid 建议填（privateinfo 才强制） | path/91022 |
| code 换身份 | `GET /cgi-bin/auth/getuserinfo`，code 一次性、5 分钟过期；回调域名须完全匹配应用可信域名否则 50001；企业成员返回 userid，非企业成员返回 openid + external_userid | path/91023 |
| 微信端前提 | 43004："指定的 userid 未绑定微信或未关注微信插件"；排查："需要成员使用微信登录企业微信或者关注微信插件" | path/90313 |
| 手机号换 userid | `POST /cgi-bin/user/getuserid`，**自建应用 token 可调**，须拥有该成员查看权限；查无报 46004；错误率封禁见上 | path/95402 |
| 创建成员 | `POST /cgi-bin/user/create`，**仅通讯录同步助手或第三方通讯录应用可调用**；userid/name 必填，mobile 不能与 email 同时为空，mobile 企业内唯一（唯一性冲突即"已入录"信号，降级 getuserid） | path/90195 |
| 客服图片消息 | kf send_msg 支持 image（先上传临时素材），touser=external_userid，48h/5 条窗口原文确认 | path/94677、path/90253 |
| 投递失败事件 | **不存在**：官方「接收消息与事件」与「发送应用消息」均无投递失败/拒收回调；errcode=0 仅代表提交成功，超频消息静默丢弃且接口不报错——送达判定不依赖任何失败事件 | path/90236、path/90930 |
| 可信域名 | 须 ICP 备案 + 上传 WW_verify 归属校验文件 | 管理后台「网页授权及JS-SDK可信域名」 |

**待真机钉死两项（前置验证）**：① 本企业微信插件可用性与真机收消息——整个无窗口通道的全局前提，项目文档亦标注"真机全流程未验收"；② 微信端 OAuth 对插件关注者返回 userid——机制有 43004 文案与返回结构支撑，官方未在授权链接页明说。②不通过 → OAuth 主映射失效、全员走手机号辅映射，流程因关注前置重排仍然成立，只是放弃"零输入"卖点。

## 前置条件与交接约定

| # | 事项 | 说明 |
|---|---|---|
| 1 | 可信域名（P1 前提） | 自建应用配置「网页授权及JS-SDK可信域名」：ICP 备案 + 归属校验文件。未就绪时 OAuth 按钮隐藏，先上手机号路径与确认闭环，CLI 继续兜底 |
| 2 | 真机验证 ×2 | ①管理后台「我的企业 → 微信插件」可生成邀请二维码且真机可收应用消息；②可信域名就绪后微信端 OAuth 静默返回 userid。②不通过 → 映射退化为手机号路径；①不通过 → 无窗口通道本身存疑，应用消息腿降级为微信测试号+自定义模板消息（oauth/绑定/确认机制与本提案同构，换 appid 即复用），本提案收缩为绑定与确认闭环部分，不再悬置触达决策 |
| 3 | 通讯录查看权限（手机号路径前提） | 自建应用可见范围覆盖目标成员；部署机出口 IP 加入企业可信 IP（家宽动态出口须固定，否则 gettoken 被拒） |
| 4 | 未验证企业权限面核验 | 主体为个人、企微必然未验证：核验通讯录同步助手与 user/create 可用性（决定自助入录开关是否隐藏）、微信插件入口（并入 #2 ①）、可信域名与可信 IP 配置入口是否开放；不可用面按降级规则处理，不阻塞 P1 |
| 5 | 通讯录同步 secret（自助入录前提，可选） | 管理后台「管理工具 → 通讯录同步」开启 API 接口同步，secret 注入 `.env` 不入仓；未配置则 `PUSH_SELF_ENROLL=false`，未命中手机号只提示 |
| 6 | 新增配置项 | `WECOM_CONTACT_SECRET`（可选）、`PUSH_SELF_ENROLL`（默认 false）、`PUSH_STATE_TTL`（默认 600 秒） |
| 7 | 实施顺序 | 若 update-postgres-storage 已合入，本变更按 async PG 落地、加列进其 PG 终态 DDL；否则按现行 SQLite 实现并在该变更收编 |

- `src/homeshield/core/repo.py` — `wecom_member` 加列（bound_via/bound_at/verified_at/last_fail_at）与绑定状态方法；

## 时间线评估

中（单人）：P1（关注前置 + OAuth 映射 + 送达确认 + 状态 + CLI 退役）约一天；手机号路径半天；自助入录半天（配置占比高）；控制台与异常态半天；两项真机前置验证合计半小时。

## 风险

- **微信插件可用性存疑**（社区反映新企业入口弱化、无官方下线公告）→ 前置验证第一项；不通过则应用消息腿降级为微信测试号+自定义模板消息腿（oauth/绑定/确认机制与本提案同构，换 appid 即复用），本提案收缩为绑定与确认闭环部分，不再悬置触达决策。
- **备案域名周期不可控** → P1 与手机号路径解耦，域名未就绪先上手机号 + 确认闭环，CLI 兜底。
- **OAuth 微信端行为与文档表述不完全一致** → 真机验证前置；因关注前置重排，失败模式只剩"全员走手机号辅映射"一种，主路径零输入卖点失效但流程不空转。
- **getuserid 错误率封禁（超企业人数 20% 封 1 天）** → 仅用户自报触发 + 失败计数护栏 + 格式预校验（预校验失败不计数）。
- **通讯录写权限面扩大** → 自助入录默认关、显式开关；未验证企业下以交接约定 #4 核验为准；绑定来源字段留痕，异常解绑一键可达。
