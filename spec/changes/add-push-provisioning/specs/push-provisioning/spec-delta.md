# 规范差异：push-provisioning（联防者推送通道自助开通）

本文件包含对 `spec/specs/push-provisioning/spec.md` 的规范变更（全新能力，全部为 ADDED）。

## ADDED Requirements

### Requirement: 绑定入口统一为带凭证的开通链接
推送开通 SHALL 以客服会话/控制台下发的带 token 链接为唯一入口（复用现有 `_send_console_link` 与 alert 链接的凭证模式）；开通页 SHALL 据此确定内部 user_id，并以一次性、短时效的 OAuth state 承载该映射。无凭证或过期 state 的绑定请求 SHALL 一律拒绝。

#### Scenario: 无凭证访问开通页
GIVEN 请求未携带任何绑定凭证
WHEN 访问开通页或 OAuth start
THEN 返回引导文案（经客服会话重新下发链接）
AND 不进入授权流程

### Requirement: OAuth 身份映射（主映射）
WHEN 已关注插件的用户在开通页发起授权，
系统 SHALL 构造企业微信网页授权链接（scope=snsapi_base，redirect_uri 指向本服务回调地址，state 携带一次性且短时效的绑定凭证及其 user_id 映射），并在授权回调中以 code 换取成员身份、仅当返回成员 userid 时将该 userid 绑定至对应控制台用户。

#### Scenario: 已入录成员一键绑定成功
GIVEN 用户已在企业通讯录且其微信已关注微信插件
WHEN 用户点击「开通推送」并完成授权，企微回调携带 code
THEN 系统以 code 换取 userid 并将该用户与 userid 建立绑定
AND 记录绑定来源为 oauth 与绑定时间
AND 控制台呈现「已绑定」

#### Scenario: 非成员身份不绑定
GIVEN 打开授权链接者为普通微信用户（非企业成员）
WHEN code 换取仅返回 openid/external_userid 而无 userid
THEN 系统不建立任何绑定
AND 呈现「未检测到企业成员身份」及进入手机号分支的引导

#### Scenario: 绑定凭证防重放
GIVEN 回调 state 已被使用或已超过有效期
WHEN 携带该 state 的回调到达
THEN 系统拒绝本次绑定
AND 要求用户重新发起开通

#### Scenario: 换取失败可诊断
GIVEN code 换取返回 invalid code（40029），或回调域名与应用可信域名不匹配（50001）
WHEN 系统处理回调
THEN 呈现对应原因与检查项（如「可信域名未配置」）
AND 不建立绑定

### Requirement: 手机号自助绑定与入录
WHEN 用户在控制台提交本人手机号，
系统 SHALL 以手机号换取 userid 的接口探测；命中 SHALL 绑定该 userid（来源 mobile）；未命中 SHALL 依据自助入录开关分别处理；探测失败 SHALL 受护栏约束以防触发企微错误率封禁。

#### Scenario: 命中已入录成员
GIVEN 提交的手机号对应企业通讯录成员
WHEN 用户提交手机号
THEN 系统建立该用户与对应 userid 的绑定，来源记录为 mobile
AND 控制台呈现「已绑定」

#### Scenario: 未命中且开启自助入录
GIVEN 自助入录开关已开启
WHEN 用户提交通讯录中不存在的手机号
THEN 系统调用创建成员接口登记该手机号并完成绑定
AND 控制台呈现「已绑定」

#### Scenario: 创建冲突降级重试
GIVEN 自助入录已开启且提交的手机号在企业通讯录中已存在
WHEN 创建成员接口因手机号唯一性约束而失败
THEN 系统降级以手机号换取 userid 重试一次
AND 换取成功后完成绑定

#### Scenario: 未命中且未开启自助入录
GIVEN 自助入录开关未开启
WHEN 用户提交通讯录中不存在的手机号
THEN 系统呈现「该手机号未在企业通讯录，请联系管理员加入后再试」类引导文案
AND 不建立绑定

#### Scenario: 探测失败护栏
GIVEN 短时间内未命中的探测累计超过阈值
WHEN 用户再次提交手机号
THEN 系统拒绝本次探测并提示稍后再试
AND 防止触发企微「错误次数超企业人数上限 20% 封禁 1 天」的接口保护

#### Scenario: 格式非法不计配额
GIVEN 用户提交的手机号格式非法
WHEN 提交到达
THEN 系统拒绝并提示格式错误
AND 本次提交不计入探测失败护栏计数

### Requirement: 插件关注前置（第一屏下发）
关注微信插件是无窗口触达的物理前提（43004），也是 OAuth 微信端成员识别的依据：开通流程 SHALL 以插件关注为第一屏动作，对所有人无条件先行。开通页首屏 SHALL 呈现插件邀请二维码，并 SHALL 优先经用户客服会话发送同一二维码图片与操作文案；会话窗口不可用或发送失败时 SHALL 在控制台提供同一二维码图片作为兜底。系统 SHALL NOT 在用户关注插件前将通道呈现为可用。

#### Scenario: 首屏下发二维码
GIVEN 联防者打开开通页且在 48 小时窗口内与客服有过消息往来
WHEN 开通流程开始
THEN 该用户客服会话收到插件邀请二维码图片与说明文案
AND 开通页首屏呈现同一二维码

#### Scenario: 窗口失效时控制台兜底
GIVEN 用户超过 48 小时窗口，或图片发送失败，或用户身份非客服会话用户
WHEN 开通流程开始
THEN 控制台首屏展示同一二维码图片与文字指引
AND 流程不报错中断

#### Scenario: 未关注插件不得进入就绪态
GIVEN 用户尚未关注微信插件
WHEN 查看推送通道状态
THEN 状态不为送达就绪
AND 下一步动作引导为扫码关注插件

### Requirement: 送达确认单信号闭环
WHEN 用户完成绑定，
系统 SHALL 发送一条测试应用消息（含回到控制台的确认链接）；
WHEN 用户确认收到，系统 SHALL 将通道标记为送达就绪；
WHEN 测试消息发送返回同步错误（如 43004 未关注插件）或确认超时，系统 SHALL 将通道标记为异常并呈现原因与下一步；
IF 超时未确认，系统 SHALL 在控制台呈现「未确认」提示与重测入口；
IF 通道处于异常或未确认状态，系统 SHALL 保证告警提醒仍经客服会话回落送达，不因应用消息通道异常而中断。
送达判定 SHALL NOT 依赖任何应用消息投递失败回调：官方「接收消息与事件」与「发送应用消息」均无投递失败/拒收事件（errcode=0 仅代表提交成功，超频消息静默丢弃且接口不报错）；日后官方补齐该事件可叠加为增强，不作为本能力承诺。

#### Scenario: 确认后就绪
GIVEN 用户已绑定且收到测试应用消息
WHEN 用户在控制台确认收到
THEN 通道标记为送达就绪
AND 后续该用户的判定告警经应用消息投递

#### Scenario: 同步报错入异常态
GIVEN 测试应用消息发送返回 errcode≠0（如 43004 未关注插件）
WHEN 系统处理该响应
THEN 对应用户通道标记为异常并记录原因
AND 控制台呈现异常原因与下一步指引（如重新扫码关注插件）

#### Scenario: 超时未确认
GIVEN 用户已绑定但超过确认时限
WHEN 查看推送通道状态
THEN 呈现「未确认收到」提示与重发测试消息入口

#### Scenario: 通道异常时提醒不中断
GIVEN 某联防者推送通道处于异常或未确认状态
WHEN 其被联防者的查询判定完成并产生提醒
THEN 提醒记录照常生成并经客服会话回落尝试触达
AND 不因应用消息通道异常而丢失或延后提醒记录

### Requirement: 推送通道状态呈现与解绑
WHERE 联防者打开控制台，
系统 SHALL 展示推送通道状态（未绑定 / 已绑定未确认 / 送达就绪 / 异常）与对应下一步动作入口；
WHEN 用户选择关闭推送，
系统 SHALL 解除绑定，自此该用户的告警不再经应用消息投递，而提醒记录、实时流与客服会话回落不受影响。

#### Scenario: 状态展示
GIVEN 联防者打开控制台的推送通道设置区
WHEN 页面加载
THEN 呈现当前四态之一及对应入口（未绑定→开通按钮；已绑定未确认→确认/重测；送达就绪→无动作；异常→原因与修复指引）

#### Scenario: 解绑后仅回落
GIVEN 用户选择关闭推送
WHEN 其被联防者的查询判定完成并产生提醒
THEN 该用户不再收到应用消息
AND 提醒记录、控制台实时流与客服会话回落行为不变

#### Scenario: 重新开通换绑
GIVEN 用户此前已解绑或需更换绑定的 corp_userid
WHEN 用户重新完成开通流程
THEN 新绑定生效且旧映射被替换
AND 通道状态回到已绑定（未确认）

### Requirement: 未验证企业前提
运营主体为个人、企业微信必然处于未验证状态：自助入录、微信插件、可信域名/可信 IP 等机制 SHALL 以未验证企业实际可用性为准；不可用的路径 SHALL 按降级规则隐藏或退化，SHALL NOT 假设验证企业权限。

#### Scenario: 自助入录不可用时隐藏
GIVEN 未验证企业下通讯录同步助手/user-create 不可用
WHEN 手机号探测未命中
THEN 呈现引导文案而非入录表单
AND 自助入录开关强制关闭
