# 端到端真机验收操作指南（add-push-provisioning）

覆盖 tasks.json 阶段 0（企微后台配置与前置验证）与阶段 8（端到端验收）。
每步给出：操作 → 预期 → 失败判读。验收记录填 §6 表格，完成后按 §7 收口。

## 0. 参与者与准备

- **运营者**：企微管理后台管理员权限 + 部署机访问权。
- **两个真实微信**：A = 查询者（被联防者），B = 联防者。建议两台手机两个人；一人两个微信号亦可，但插件消息与客服会话的到达观感会打折。
- 服务已部署、公网域名可访问（下文以 `https://shield.example` 指代 `PUBLIC_BASE_URL`）。
- 手头备好截图工具；全程开着服务日志（`docker compose logs -f app` 或 `journalctl -u homeshield -f`）。

## 2. 真机前置验证 ×2（两项不过各自触发预案）

### 验证① 插件链路（整个无窗口通道的全局前提）

1. 在企微后台通讯录**手动添加 B 为成员**（手机号 + 姓名），记录手机号。
2. B 用微信**扫码关注微信插件**（1.2 的二维码）。
3. 部署机上执行（自动完成 手机号→userid→发应用消息）：

   ```bash
   uv run python - <<'EOF'
   import asyncio
   from homeshield.core.config import Settings
   from homeshield.core.channels.wecom import WeComChannel

   async def main():
       ch = WeComChannel(Settings.load())
       mobile = "填B的手机号"
       userid = await ch.get_userid_by_mobile(mobile)
       print("userid:", userid)
       print(await ch.send_app_message([userid], "推送通道验证：在微信看到这条即插件链路可用。"))

   asyncio.run(main())
   EOF
   ```

4. **预期**：B 的微信「微信插件」会话收到该消息；脚本输出 `errcode: 0`。
5. **失败判读**：`errcode 43004` → B 未关注插件或手机号未绑定微信；`60020` → 可信 IP 不符； userid 为 `None` → 手机号不在通讯录。结果记入交接约定 #2①。

### 验证② 微信端 OAuth 返回 userid（决定主路径成立性）

1. 先让 B 获得个人 token：B 在微信里给客服小盾发「我的联防」→ 客服会话回控制台链接（含 `?token=`）。
2. **在 B 的微信里**打开：`https://shield.example/wecom/oauth/start?token=<B的token>`。
3. **预期（通过）**：静默跳转后回到控制台，推送通道显示「已绑定，等待确认测试消息」，且 B 的微信插件收到测试消息 → OAuth 返回 userid，主路径成立。
4. **预期（预案）**：跳回后提示「未检测到企业成员身份」→ OAuth 只返回 openid → **全员转手机号辅映射**（流程仍成立，本提案已为此重排）；提示「可信域名未配置」→ 回查 1.4。结果记入交接约定 #2②。

## 3. 端到端主流程验收（任务 10 ②）

> 前置：验证①已过；B 在通讯录中。A、B 均为真实微信。

| 步 | 操作（谁） | 预期 |
|---|---|---|
| 1 | A 给小盾发任意可疑消息 | A 收到判定回复 +「你的个人控制台:…」链接（A 建身份） |
| 2 | B 给小盾发「我的联防」 | B 收到控制台链接（B 建身份，留好 token） |
| 3 | A 给小盾发「邀请 妈妈」 | A 收到邀请码 |
| 4 | B 给小盾发「绑定 <邀请码>」 | B 收到「已建立联防关系」回复 |
| 5 | B 打开自己的控制台 →「推送通道」页签 | 显示「未开通推送」；**首屏二维码卡可见**；同时 B 的客服会话收到二维码图片+引导文案 |
| 6 | B 扫码关注微信插件（若 2① 未做过） | 关注成功 |
| 7 | B 点「开通推送」 | 微信内静默授权 → 跳回控制台「已绑定，等待确认测试消息」；**B 的微信插件收到测试消息**（含确认链接） |
| 8 | B 点测试消息里的确认链接 | 跳回控制台，显示「确认完成」→ 状态「送达就绪」 |
| 9 | 状态核对 | B 控制台状态灯=送达就绪，绑定方式=微信授权 |
| 10 | **触发真实告警**：A 给小盾发高危消息（如「别告诉家人，马上转账到这个账户…」） | A 收到判定回复；**B 的微信插件实时收到**「⚠️ 高危预警：你护着的『妈妈』查询了可疑消息…详情：…」；详情链接可打开落地页；服务日志无异常 |

## 4. 回归验收（任务 10 ③）

| 项 | 操作 | 预期 |
|---|---|---|
| 解绑回落 | B 控制台「关闭推送」→ 确认；A 再发一条高危 | B 不收应用消息；B 48h 内与客服有过往来 → 客服会话收到告警文案（回落）；B 控制台「我收到的提醒」记录仍在 |
| 重新换绑 | B 再次「开通推送」→ 确认 | 状态回「已绑定（未确认）」→ 确认后「送达就绪」 |
| 手机号路径·开关关 | B 解绑后，推送页签用**手机号表单**提交 B 的手机号（`PUSH_SELF_ENROLL=false`） | 命中即绑定 → 测试消息 → 确认就绪；提交陌生手机号 → 引导文案「不在企业通讯录…」，不创建成员 |
| 手机号路径·开关开 | `.env` 加 `WECOM_CONTACT_SECRET` + `PUSH_SELF_ENROLL=true` 重启；B 解绑后提交**未入录**手机号 | 自动创建成员并绑定（企微通讯录多一条「联防-××××」）；手机号已存在时降级为探测绑定，不报错 |

## 5. 常见错误速查

| 现象 | 原因 → 处理 |
|---|---|
| 发应用消息 `errcode 43004` | 成员未关注微信插件/未绑定微信 → 引导扫码（本流程第 6 步） |
| OAuth 回调「可信域名未配置」(50001) | 可信域名未配或不匹配 → §1.4；确认走的是 `PUBLIC_BASE_URL` 同域名 |
| `errcode 40029` | code 已用过/过期 → 回控制台重新点「开通推送」 |
| gettoken `errcode 60020` | 出口 IP 不在可信 IP → §1.5 更新 |
| getuserid `46004` | 手机号不在通讯录 → 入录或改用 OAuth |
| user/create `60103` | 手机号已存在 → 系统自动降级探测绑定，无需处理 |
| 二维码卡不显示 | `deploy/assets/wecom_plugin_qr.png` 缺失 → 放置文件（控制台与服务端同路径） |
| 状态一直「已绑定未确认」 | B 没点测试消息里的确认链接 → 重发测试消息 |
