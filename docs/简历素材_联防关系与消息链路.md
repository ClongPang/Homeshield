## 一、项目定调(一句话与背景)

- **家中盾(Homeshield)**:家庭反诈联防层。家人收到可疑消息,截图/转发给微信客服号「小盾」,秒级返回判定与解释;判定高危时自动提醒联防的家人;家人的纠正回流为评测样本。
- 形态:自托管网络服务(非 App、非小程序),微信客服会话为主入口,网页控制台为辅;零注册——微信会话即身份。
- 技术栈:Python 3.12 / FastAPI / SQLite(WAL)/ httpx / cryptography;LLM 为 OpenAI 兼容双供应商(DeepSeek 判定 + Qwen 向量);部署 macOS launchd 守护进程 + Cloudflare Tunnel 内网穿透。
- 来源:`pyproject.toml`、`README.md`、`.env`

## 二、双边关系模型素材

### 2.1 模型语义(是什么)

- **有向边**:`guard_relation(protector, protected)`——联防者(protector)护着被护者(protected);A 发「邀请 妈妈」、妈妈绑定后,A 成为妈妈这条边上的联防者,**A 收到妈妈的高危提醒**。
- **双向互护 = 两条独立有向边**:母女互护不是一条关系,是两次邀请建立的两条边;每条边可独立静音、独立解除。
- **受理时快照**:查询受理瞬间快照查询者的活跃 incoming 关系;判定高危只为**仍活跃**的快照关系创建提醒。解除关系后无法查看该关系收到的历史提醒(隐私设计:退出的联防者不留存他人风险记录)。
- **静音粒度**:每条边独立静音应用消息;提醒记录与 SSE 不受静音影响。
- **纠正与投票(质量回流)**:危险判定由收到提醒的活跃联防者投票;低风险判定由查询者主动反馈后,快照中的活跃联防者投票;**票数 > 半数确认**(`eligible//2+1`),零票或期限内无多数 = `no_consensus`。查询者的普通反馈不计入投票。
- **容量与期限**:`MAX_RELATIONS=10`(进出合计活跃关系)、邀请码 7 天有效、投票期 7 天。
- 来源:`core/db.py`(schema)、`core/relations.py`、`README.md` 关键行为节

### 2.2 为什么是双边而不是群(核心优势与取舍)

**群模型当初为什么合理(它的真优势,不是稻草人)**
- 心智零教育:家庭在微信里的原生形态就是群,"拉你进防护群"人人能懂;
- 建边成本 O(n):一次入群,全家互为联防,无需两两邀请;
- 家庭全景:群内共享提醒上下文,任何人可见家庭的风险事件流;
- 群级治理:信任位、群生命周期等治理能力(原型期已完整实现并上线)。

**但群模型成立依赖三个前提,2026 年的微信上全部崩塌(介质事实)**
- 前提①用户能把可疑内容带进群/发给群侧自动化角色 → 长按转发搜不到任何公众号(真机多轮实测,含真实认证服务号;微信 8.0.28 起收窄);
- 前提②高危时群级触达 → 新注册服务号无模板消息;企微互通群(含微信用户)不能加机器人,会话存档需付费+认证;
- 前提③群有合法承载物 → 公众号、企微客服两种合法介质上都建不出"含家人的可自动化群"。

**判据:群模型的全部优势都押在"群在微信侧真实存在且可自动化触达"上——前提死了,优势归零;而它的成本(群级可见性)依然存在。**

**双边模型的真优势(不只是退而求其次)**
- 与 1:1 会话同构:每条边 = 两条独立客服会话,在合法介质上零承载成本;
- **隐私粒度结构性升级**:群模型下提醒是群级可见的(所有成员看到所有风险事件);双边下联防者只看到自己护着的人的风险——查询者的暴露面从"群"缩小到"护着我的具体的人";
- 告警按边精准投递:谁护着谁就提醒谁,天然不打扰无关家人;
- 边级治理:每条边独立静音/解除,无群级状态牵连。

**双边模型的真代价(诚实列出)**
- 建边成本 O(n²):n 人家庭全员互护需每对方向各建一条边(n(n-1)/2),群是一次入群;
- 家庭全景丧失:没有任何人能看到全家风险流(用隐私换的——这也是产品边界:周报按人给,没有"全家风险流"功能);
- 投票人数退化:单人联防的家庭,投票退化为单人确认,视角比群模型的多人投票窄;
- 心智教育成本:「邀请/绑定」两步动作 vs 拉人进群,需要欢迎语与命令话术承担教育;
- 迁移成本:关系模型不迁移旧群数据库,开发库重建。

**一句话取舍:用家庭全景与建边便利,换可落地的介质与最小可见性。**在"介质不可选"的约束下这不是二选一,而是唯一解;理解这笔账,才能解释产品边界为什么长成今天这样。

### 2.3 模型在企微客服上的介质映射(怎么落地)

| 模型概念 | 微信客服上的体现 |
|---|---|
| 用户身份 | 每个家人一条与小盾的独立 1:1 会话;`external_userid` → `wxkf:` 前缀 → user 记录 |
| 建立边 | 两步、两个会话:邀请方「邀请 称呼」拿码;被邀方在自己会话「绑定 邀请码」 |
| 边的存在感 | 会话内「我的联防」文本清单 + 个人控制台链接(token 即凭证) |
| 查询 | 被护者会话内发内容,**判定只回本人**(1:1 会话天然私密) |
| 高危告警 | **跨面投递**:不走对方客服会话(有 48h/5条窗口),走企业微信应用消息 → 微信插件(无窗口、无审批) |
| 纠正 | 不在会话内;走个人控制台链接与提醒详情页 |

- 来源:`api/wecom.py`、`core/commands.py`、`core/notifier.py`、本轮设计记录

## 三、消息链路素材(端到端)

### 3.1 全链路时序(一条可疑消息的旅程)

```
家人在小盾会话发送 文字/截图/链接卡片/合并转发
  ↓ 企微实时推送 kf_msg_or_event(AES 加密报文)
自建回调 /wecom/callback:验签(msg_signature SHA1)→ AES-CBC 解密(receive_id 校验)→ 5s 内 ACK
  ↓ 事件触发即时拉取(60s 慢轮询兜底,共享游标 + 串行锁)
sync_msg(显式 open_kfid)拉取消息
  ↓ 派发
身份解析:external_userid → wxkf: 前缀 → user(首条自动建户 + 补发个人控制台链接)
指令分流:邀请/绑定/我的联防/解除/旧命令迁移提示(core/commands,通道无关)
triage 分流:会话重置 / 确认型 ACK / 完整查询
  ↓ 幂等 ingest(msg_id 唯一索引——重启重放安全)
事件分区(incident):受理时快照活跃关系 + session_epoch
  ↓ 判定管线
归一化 → 规则特征抽取(词表 + 确定性风险下限)→ 案例检索(向量 + 关键词,反诈判例库)
→ LLM 约束判定(引用校验 + 置信门槛 60 + 重试 3 次)→ 不过门槛则降级(规则下限兜底口径)
  ↓ 回复
三段式判定(【结论】【依据】【建议】)经 kf send_msg 回本人
  ↓ 高危时
VerdictCompleted 事件 → AlertRouter → 应用消息直达联防者微信插件(无窗口)→ 查询者收到"已加入谁的提醒列表"
```
- 来源:`api/wecom.py`、`core/pipeline.py`、`core/judge.py`、2026-09-28 19:04 真实运行日志

### 3.2 可靠性设计(面试可展开的四个点)

1. **幂等与重放安全**:消息 `msg_id` 唯一索引;拉取游标仅存内存,服务重启后全量重放,靠幂等去重保证零重复回复(有专门测试)。
2. **事件驱动替代盲轮询**:最初 5 秒盲轮询撞上企微 sync_msg 频控(45009,105 分钟 385 次);改为**回调通知触发即时拉取 + 60 秒兜底轮询**(共享游标与锁),API 调用量 **17,280 → 1,440 次/天(-92%)**,修复后 **37+ 分钟零限流**(日志对比:最后一条 45009 = 18:24:48,旧代码存续期 105 分钟攒 385 次)。
3. **频控自愈语义**:限流发生时游标不推进,消息由企微服务端保留,下一轮自动补拉;最坏代价是单条消息延迟回复,不丢失。
4. **降级链(通道必有回复)**:图片转写失败 → 降文本提示;LLM 失败/置信不过 → 降级口径回复且**不低于规则下限**(规则层确定的骗术特征必须陈述,说"拿不准"不得低于确定性结论);管线意外异常 → 兜底文案。降级不落判定记录(宁可拿不准,不硬判)。
- 来源:`api/wecom.py` docstring、`core/pipeline.py` 降级分支、2026-09-28 运行日志对比

## 四、写 bullet 的角度与量化钩子

- **角度 A(消息链路/架构)**:事件驱动的消息链路——回调验签解密、通知触发拉取、幂等去重、多级降级,通道必有回复
- **角度 B(关系模型)**:以有向信任边替代群容器,与 1:1 客服会话介质同构;受理时快照 + 事后活跃校验的最小可见性设计
- **角度 C(可靠性)**:频控自愈、幂等重放、降级纪律(规则下限兜底 LLM)
- **角度 D(安全隐私)**:判定私密(只回本人)、告警快照、解除即失访、AES 验签解密、token 卫生
- **量化钩子**:202 测试 / -92% API 调用 / 45009→0 / ~10s 端到端 / 0 元通道成本 / 5 类消息形态
- **动词建议**:设计、实现、收敛、替换(模型)、迁移(介质)、审计修复——避免"参与""熟悉"
