## 1. 系统架构

### 1.1 判定管线
```
                    ┌────────────────────────────────────────┐
 ┌──────────┐ text  │  intake 归一化                          │
 │ 长辈聊天页 │──────▶│  → Message{type, content, member, ts}  │
 │ (web/)    │ url  │└───────────────┬────────────────────────┘
 └──────────┘ img   │                ▼
                    │  features.py  规则抽取 + LLM 补抽
 ┌──────────┐       │  → [Feature{id,type,value,span,source}]        0.5s
 │ 判定引擎   │       │                ▼
 │ core/     │◀─────│  retrieval.py  混合检索知识库 top-2             0.3s
 └──────────┘       │                ▼
                    │  judge.py     分级判定(LLM,约束引用特征ID)
                    │  → {level, cited_ids[], reason}                4.0s
                    │                ▼
                    │  validate     引用校验(失败重试≤2)
                    │                ▼
                    │  reply.py     大白话三段式生成                  2.0s
                    │                ▼
                    │  落库(verdict) → dangerous? → notifier(SSE)   <0.5s
                    └────────────────────────────────────────┘
```

**管线约定**:
- 检索 query 由规则特征构造;LLM 补抽与检索并行、补抽结果只喂 judge;
- judge prompt 声明检索案例仅供类目知识与应对建议、"相似≠诈骗",防检索锚定误报;
- **延迟为设计参考值(非验收标准)**:上图各阶段秒数仅用于模型选型与管线结构决策;端到端目标 10s 量级——"秒级判定"是产品 UX 阈值(长辈的等待上限),不是工程验收门槛;延迟只作为评测指标报告(§6.2),不作为 done-when。超时应对:生成阶段先回"结论行"再补依据(流式)。

### 1.2 双模式
`MockJudge`(纯规则:关键词+特征计数打分,确定性)与 `LLMJudge` 实现同一 `Judge` 接口,`.env` 的 `MODE` 切换。Mock 仅做 CI 回归与离线演示;消融矩阵在 LLM 模式下跑(§6.3)。

## 2. 接入通道
- **微信(长辈主入口)**:演示用公众平台测试号(客服接口/模板消息免认证开放,平台规则核验于 2026-09,备选方案取舍见《产品定位》§4.2)。回调按消息类别派发,家人在 5s 窗口内得到可见回应:开通/绑定命令(`开通`、`绑定 <码>`)同步回执行结果(纯 DB 操作),文字/图片回执"收到,正在帮你看…",语音/视频等暂不支持类型立即回兜底提示(请打字或发截图),关注事件回欢迎语(含开通/绑定指引);正式判定经客服接口异步回复(48h 内 5 条额度)。生产用认证服务号:客服接口异步回复 + 模板消息告警,接入阶梯写进 README(《产品定位》§3 D4)。
- **多租户入家(src/homeshield/core/binding)**:一个部署 + 一个公众号服务多个家庭。自助开通:陌生 openid 回复`开通`→ 建家庭并发送者成为管理员(adult);邀请绑定:管理员在控制台为家人创建成员位并生成 8 位一次性绑定码(默认 7 天有效,重发即作废旧码),家人回复`绑定 <码>`把 openid 落到成员位。未绑定的其他消息只引导不判定(不落库、不耗判定资源);护栏 `MAX_FAMILIES`(全局家庭数)×`MAX_MEMBERS`(每家成员数),一人一家由 `member.openid` UNIQUE 保证。
- **网页聊天页(兜底)**:粘贴文字或上传截图,归一化进同一 intake(§1.1)。
- **告警双通道**:dangerous → 模板消息推送到 adult 微信并携带详情落地页链接(点击直达该条判定与一键反馈);在线控制台经 SSE 实时同步并支持历史回放(打开时先渲染历史,推送只补增量)。模板消息无 48h 限制,定位"用户触发后的通知",家人关注并同意接收,合规。
- **异常与守护**:管线意外故障在 VerificationService 收口为人话兜底回复,家人不会遇到 500 或沉默;进程由 systemd / launchd 单元守护(deploy/),崩溃自动重启。

## 3. 判定与协同规则

### 3.1 告警触发
仅 `level='dangerous'` 实时 SSE 推送全家 adult;`suspicious` 只进周报(打扰预算)。

### 3.2 隔离话术策略(规则下限)
特征类型 `isolation`(初始词表:"别告诉家人/子女""保密""这是我们俩的事""影响他工作"…)命中即至少 `suspicious`;与 `transfer`(要求转账)类特征共现 → 直接 `dangerous`;规则结果为下限,最终 level = max(规则级, LLM 判定级);回复模板追加"我已经把这条消息告诉了你的家人"(回复不出现成员名,成员名仅内部字段)。

### 3.3 纠正状态机
`elder 提交 → pending →(adult confirm)confirmed / (adult reject)rejected`;`adult 提交 → confirmed`。防投毒:仅 adult 确认后(`confirmed`)的纠正视为有效样本;`pending` 超时(7 天)自动 rejected。

### 3.4 隐私规则
family 内仅共享 `query` 与其 verdict;系统无任何被动采集入口;长辈视图首次进入展示知情页("你查证的内容家人可见";承载方式见《产品定位》§1.3)。

## 4. 数据模型(SQLite,字段级)
```sql
family(id PK, name, created_at)
member(id PK, family_id FK, name, role TEXT CHECK(role IN ('elder','adult')),
       openid TEXT UNIQUE NULL,   -- 微信零注册映射(公众号内唯一)
       token TEXT UNIQUE NULL,    -- 个人链接凭证(链接即凭证)
       created_at)
bind_code(id PK, code TEXT UNIQUE, member_id FK, created_by FK NULL,
          created_at, expires_at, used_at NULL)   -- 一次性入家凭证,领取/过期/重发即失效
query(id PK, family_id FK, member_id FK, content_type TEXT CHECK(content_type IN ('text','url','image')),
      content TEXT,          -- image 存 base64 或本地路径
      created_at)
verdict(id PK, query_id FK, level TEXT CHECK(level IN ('safe','suspicious','dangerous')),
        cited_ids TEXT,      -- JSON 数组,如 ["F01","F04"]
        features TEXT,       -- 全量特征快照(JSON),供纠正回流复盘与消融分析
        reason TEXT, reply TEXT, latency_ms INT,
        mode TEXT CHECK(mode IN ('mock','llm')), created_at)
alert(id PK, verdict_id FK, member_id FK, delivered_at INT, read_at INT NULL)
correction(id PK, verdict_id FK, by_member_id FK, label TEXT CHECK(label IN ('real','false_positive','confirmed_scam')),
           -- label 语义: false_positive=误报; real=漏报(提交时); confirmed_scam=real 经 adult 确认后落库
           note TEXT, status TEXT CHECK(status IN ('pending','confirmed','rejected')),
           decided_by INT NULL, created_at, decided_at NULL)
```

**关键约束**:`alert` 仅由 `level='dangerous'` 的 verdict 触发(应用层保证);`correction.status` 状态机见 §3.3;纠正样本留存于库,不参与在线判定。

## 5. API 契约

家人接口以 token(不可枚举)定位成员,无/错 token 一律 401,接口不回传 token。多租户:成员经`开通`/`绑定码`入家(§2);所有家人数据按 `member.family_id` 隔离(告警跨家庭 404,纠正提交/裁决跨家庭 400);成员管理仅 adult。

| 方法/路径 | 请求 | 响应 | 说明 |
|---|---|---|---|
| POST `/api/query` | `{token, content, content_type?, msg_id?}` | `{query_id, verdict_id, level, cited_ids, reply, latency_ms}` | 同步返回判定;dangerous 时异步广播 |
| GET `/api/stream?token=` | — (SSE) | `event: alert, data: {verdict 摘要}` | 子女控制台订阅 |
| GET `/api/alerts?token=` | — | `{alerts: [{verdict_id, level, summary, delivered_at}]}`(新→旧,按判定去重) | 高危告警历史:控制台打开时先渲染,SSE 只补增量 |
| GET `/api/alerts/{verdict_id}?token=` | — | `{level, reply, summary, created_at, my_feedback}` | 单条告警详情(落地页数据,含本人反馈状态);跨家庭 404 |
| GET `/alert/{verdict_id}?token=` | — | 静态页 | 告警落地页:详情 + 一键反馈(误报 / 真骗局) |
| GET `/api/corrections?token=` | — | `{pending: [{id, label, note, content, by_name, created_at}]}` | 待确认纠正队列(仅 adult 可操作) |
| POST `/api/corrections` | `{token, verdict_id, label, note?}` | `{correction_id, status}` | adult→confirmed;elder→pending |
| POST `/api/corrections/{id}/confirm` | `{token, decision?}`(confirm/reject) | `{status}` | 仅 adult |
| GET `/api/members?token=` | — | `{members: [{id, name, role, bound}]}` | 成员列表(不含凭证;bound=openid 是否已绑) |
| POST `/api/members` | `{token, name, role?}` | `{member_id, name, role, bind_code, bind_expires_at, entry_url?}` | 创建成员位并签发绑定码;仅 adult,`MAX_MEMBERS` 封顶 |
| POST `/api/members/{id}/bind-code` | `{token}` | `{bind_code, bind_expires_at}` | 重发绑定码(作废旧码);仅 adult 同家庭,成员须未绑定 |
| GET `/api/weekly?token=` | — | `{queries, dangerous, false_positives, corrections}` | 周报 |
| GET `/` 、 GET `/console` | — | 静态页 | 长辈聊天视图 / 子女控制台(链接即凭证) |
| POST `/wechat/callback` | 微信消息回调 | 被动回复 success/空串(ACK) | 测试号/服务号消息入口;平台签名鉴权;判定结果经客服接口异步回复 |

## 6. 评测规格

**收敛标准(评测纪律,高于本节其余内容)**:
- 唯一的质量收敛标准是**真实世界使用**:真实查询日志、confirmed 纠正(库内留存)、真机/真通道延迟;
- mock、种子样例、合成数据只有两个合法用途:① CI 管道正确性回归;② 冷启动冒烟。**禁止**作为任何质量指标(Recall/FPR/延迟)的收敛与拟合目标——对着自产数据调词表、提示词、阈值,就是"虚假环境陷阱";
- 调整纪律:词表、提示词、阈值、检索权重的每次变更,必须附真实数据复测证据(库内纠正重放或真机日志),否则不合入;
- 报告纪律:`docs/reports/report.md` 强制标注数据来源构成与模式口径;mock 口径的数字只能表述为"管道验证",不得表述为产品质量;
- 配比纪律:§6.1 的样本构成只约束冷启动集 v1;真实使用启动后,数据分布与扩充由真实回流决定,不再按预设配比制造样本。

### 6.1 数据集(`data/samples/`,JSONL,每行一条)
- **规模与构成**:80-100 条;诈骗 40 / 边缘 30 / 正常 30。
- **字段**:`{id, text, label: scam|edge|benign, scam_type(诈骗类才有,对齐分类学), source: "adapted:<出处>"|"synthetic:llm:<model>", notes}`。
- **分层要求**:scam 中 ≥20 条标注 `source=synthetic:llm:*`(由 LLM 生成+人工改写),用于"AI 生成话术检测退化"子评测(中文首发数据点,对标 Frontiers 2026 的英文结论)。
- **边缘档必须覆盖**:真实兼职群、真快递理赔、家人借钱、正常营销短信。
- **来源可溯**:来源与改编方式逐条记录 provenance,防"人造感"质疑。
- **扩展集(候选,不入 v1 主集)**:`data/samples/fraud_r1_base.jsonl`(32 条,8 类均衡,`source=synthetic:llm:deepseek-r1`,**待人工过筛**,已扫描 6/32 含生成残留)与 `data/samples/fraud_r1_levelup.jsonl`(128 条 = 32 案例 × 增强级 0~3 配对,专供"AI 生成话术检测退化曲线");`uv run homeshield-kbcli export-eval` 一条命令复现(§7.3)。

### 6.2 指标定义(公式进 `src/homeshield/eval/run_eval.py` 与报告)
- 检出率 Recall = TP / (TP+FN);TP = 标注 scam 且判为 dangerous+suspicious(dangerous 单列);
- 误报率 FPR = FP / (FP+TN);FP = 标注 benign/edge 且判为 dangerous;
- 分级混淆矩阵(3×3);延迟 P50/P95;分档报告 scam 子集(人工 vs LLM 生成)。

### 6.3 消融矩阵(全部在两种模式下跑)
| 配置 | 特征抽取 | 知识库检索 | LLM 判定约束 | 说明 |
|---|---|---|---|---|
| A(zero-shot) | — | — | 无约束 | 基线 |
| B(A+RAG) | — | ✓ | 无约束 | 检索增益 |
| C(B+约束) | ✓ | ✓ | 引用校验 | 完整方案 |

### 6.4 阈值扫描
判定置信分 → P/R 曲线;工作点按"误报权重高于漏报"选取(产品依据:误报三次=家人拉黑=产品死亡),依据写入报告。

### 7.2 安装与运行(Python 3.12,uv 管理)
- 安装:首次 `uv python pin 3.12` 固定解释器,然后 `uv add openai fastapi "uvicorn[standard]" pydantic python-dotenv httpx`、`uv add --dev pytest`(依赖进 pyproject.toml,锁定 uv.lock,自动创建虚拟环境);`uv sync` 以 editable 方式安装 homeshield 包(`[project.scripts]` 提供三个入口);
- 配置 `.env`:`MODE=llm|mock`;供应商任意命名,每个供应商三件套 `<NAME>_API_KEY / <NAME>_BASE_URL / <NAME>_MODEL`(OpenAI 兼容端点);任务分工 `CHAT_PROVIDER`(判定/补抽/回复)、`TRANSCRIBE_PROVIDER`(图片转写,留空回落 chat)、`EMBED_PROVIDER`(向量检索,留空则纯关键词);
- 运行:`uv run uvicorn homeshield.server:app --reload`;测试:`uv run pytest tests/`;入口:`homeshield-cli`(运维/演示)、`homeshield-kbcli`(离线素材库)、`homeshield-eval`(评测);
- 注意:脚本与测试统一经 `uv run` 执行,不手工 pip install;Python 3.12 下 `match`、`X | Y` 类型联合等新语法可用。

### 7.3 离线素材库(kbbuild,与运行时隔离)
- **定位**:离线批处理资产,服务链路(server/cli/core)永不读取;只有人工审核后的产出物(词表/案例/评测样本)单向进入版本库。
- **数据**:`data/kb_build.db`(`*.db` 已 gitignore):`fr_case`(Fraud-R1 中文语料 4,280 行 = 1,070 案例 × 增强级 0~3,provenance 与许可注记逐行落库)、`fr_tactic_extract`(战术挖掘,预留)、`marker_candidate`(词表审核队列,状态机仿 correction);源文件在 `data/raw/fraud-r1/`(gitignore)。
- **工具**:`uv run homeshield-kbcli init-db|import|stats|export-eval`(不依赖 .env/LLM,零运行时耦合)。
- **类目映射**:`kbbuild/mapping.py` 将 Fraud-R1 五大类对齐 12 类分类学(834/1,070 可映射);phishing 三个子类(236 条)为分类学缺口,映射外不导出,建议后续新增"钓鱼链接/中奖"类目(规格允许 ≥12 类)。
