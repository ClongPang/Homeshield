## 1. 问题陈述

**系统没有跨消息的会话概念,"一次欺诈检测"的边界被钉死在"一条消息"上。**

真实骗局是多天、多条消息的:骗子先用几天建立信任("在带你赚钱"),再在某个时刻索取("再转 5000 就能提现")。当前系统里,查询者先发一张聊天截图、十分钟后又发一句"他今天又让我转账了",第二条是完全孤立的判定——前文的信任铺垫、上一条的判定级别,对第二条判定不可见。重构四建立的"会话"没有解决这个问题,因为它只在单条消息内部成立。

用户原话(2026-09-27):"现在项目这样的欺诈检测,好像是没有会话的概念……怎么区分用户一次欺诈检测消息的边界。"

## 3. 后果

1. **判定上下文残缺**:单条截图装不下多天证据链,judge 每次只见骗局的一个切片。对渐进式骗术(杀猪盘类),单独看任何一条都可能是 safe/suspicious,连起来才是 dangerous——这正是"零漏报"目标的结构性盲区。
2. **升级特征跨消息失效**:现有 `escalation` 是规则层确定性计算,只在消息内生效;跨消息升级(同一 user 的时序消息)天然可以复用同一逻辑,但当前无挂靠点。
3. **额度浪费**:纯确认类消息消耗客服回复额度与判定成本,还可能把"谢谢"判成 safe 并落一条无意义 verdict,污染回流数据。
4. **案件视角缺失**:告警、纠正、周报都以单条 verdict 为粒度,同一骗局的多次查询无法聚合,"这周这个骗局盯上你三次"这类案件级结论无从产生。

## 4. 问题的两半

- **归属(上半)**:哪些消息属于同一次案件/会话?——§5 取舍结构、§6 方案的主题。
- **分诊(下半)**:一条消息是否构成一次检测请求?闲聊、确认、对上一条回复的感谢,不该触发判定。E4/E5 的现状是"每条都判"。

## 5. 取舍结构(先于机制选型)

### 5.1 边界误差不对称:切小是漏报级错误,切大是成本级错误

- **切小(该并未并)**:同一骗局的消息被孤立判定,judge 只见骗局切片,渐进弧不可见——直接产生漏报。这是产品最付不起的错误。
- **切大(不该并误并)**:无关消息混入前情,token 变贵、可能稀释信号、回复可能错误引用——产生误报/成本/困惑,可恢复。

推论一:**机制的默认偏向必须是"多并"**,阈值往大取,混入由其他机制兜。
推论二:**"无前情"是今天的基线,可接受的失败必须退向基线,而不是退向"喂错前情"这个新故障类**。硬二分两种失败都可能出现;相关性选取失败只会退向基线。

### 5.2 "会话"其实是两个边界,错误代价不同,不该共用一个机制

| 边界 | 服务于 | 错切代价 | 适配机制 |
|---|---|---|---|
| 案件分区(聚合/周报/纠正溯源) | 分析与产品叙事 | 便宜:归错案子只是统计噪声 | 宽时间窗 + 显式重置,确定性强 |
| 判定供给(judge 前情) | 漏报主线 | 昂贵:切碎→漏报,错喂→新故障类 | 相关性选取(确定性规则起步),失败退向基线 |

把两者合一(一个 session_id 决定一切)必然在某个主子上取错阈值。

### 5.3 上下文单向棘轮:只抬不下

1. **不注入旧判定结论**——judge 收到的是前情原文与特征,不是以前的 verdict;
2. **跨消息升级特征并入规则下限方向**(`max_level` 已保证单向);
3. 前情只可能经升级特征把判定抬高,结构上不存在"前情把 dangerous 拉成 safe"的通路。

### 5.4 消息形态即边界声明

老人发完整截图(带"对方:/我:"多轮)= 自带边界的自足工件;发孤立短句带回指词("又""还是""他""那个")= 省略句,默认需要前文。机制先读懂形态,再看时间。

### 5.5 机制对照(v1.1 讨论稿)

| 机制 | 案件分区 | 判定供给 | 失败模式 | 结论 |
|---|---|---|---|---|
| A 时间窗 | ✅ 合适 | ⚠️ 太粗:跨天长弧必被切碎 | 分区错误便宜 | 只用于分区 |
| B 语义判定(逐条问 LLM) | 不必 | ⚠️ 准但非确定、逐条成本 | "错并/错分"皆可能出现 | 实验开关,不进默认 |
| C 显式重置("新的")+信号修正 | ✅ 兜底 | ✅ 信号修正供给前文 | 用户不用兜底命令时退化为 A | 保留为兜底与修正 |
| D 相关性选取(最近带特征/带回指前文,带时限与上限) | — | ✅ 失败退向基线 | 供给不足=回到今天的单条判定 | 判定供给的主机制 |

**v1.3:方案按此结构定稿并拆为 v1/v2(§6.5)——A+C 管案件分区,v1 供给进规则层,v2 供给原文进 prompt 作门控实验。**

## 6. 方案定稿:不画边界,往前翻(2026-09-27)

### 6.1 一个场景讲清问题与解法

妈妈周一发来一张和骗子的聊天截图,周五又发来一句"他又让我转账了"。今天的系统判那句话时是失忆的——看不到周一的截图,只看到孤零零一句"转账"。这句话单独看也许只是可疑,连着前面几天的"带你赚钱""别告诉家人"看才是危险。

解法不提前画边界,改成**"判的时候往前翻"**——人类家人就是这么干的。系统照做,判任何一条新消息之前,自动把这个查询者最近的旧消息翻出来:

1. **同一个"案子"里的旧消息,全翻出来。** 案子怎么分?同一个人,两条消息间隔 ≤6 小时算同一案,超了开新案;用户发"新的"手动开新案。
2. **7 天以内、账号或链接能对上号的旧消息,也翻出来。** 抓"隔了几天、记账上已是新案、但还是同一个骗子"的情况。
3. 每条标上"这是 3 天前发的",最多 10 条,多则丢最旧。
4. 一条都翻不到?与今天完全一样,只判新消息本身。

### 6.2 两套规则、两个口径(不是设计绕了)

"边界"本来就是两个问题:记账上哪些消息算一伙(给周报/历史看,归错无所谓),判定上给 judge 看哪些(给少了会漏报)。两个问题对"切多准"的要求完全不同,所以用两套简单规则各管各的,不硬造一个"会话"概念包打天下(§5.2)。

### 6.3 为什么所有旋钮都往"多翻"拧

翻多翻少的代价不对称(§5.1):翻多了,judge 多花 token、最多被干扰——小代价;翻少了,judge 只看到"转账 5000",判成 safe,老人被骗——漏报,最付不起的代价。

### 6.4 两条保险:防止"多翻"本身闯祸

- **只给证据,不给结论。** 旧判定结果("上次判了 safe")不给 judge 看,只给旧消息的原文与特征。旧结论可能是错的,喂回去会带偏新判定。
- **前情只能抬警报,不能降。** "三天前别告诉家人 + 今天要转账"→ 判定只会往上走(已有"规则下限"逻辑延伸到跨消息),结构上不存在翻了旧消息反而判得更安全的通路。

### 6.5 v1/v2 拆分:先给特征,后给原文(v1.3)

供给的"确定性内核"和"LLM 增益"是两个风险等级,分开上线:

- **v1:供给只进规则层(supply-as-features)。** 前情不进 prompt,产出一组跨消息摘要特征进 features 列表供 judge 引用:跨消息 `escalation`("3 天前信任建立→本条索取")、isolation/transfer 跨条命中的下限抬升。兑现的恰是最高适配档(信任弧类,§6.8)的确定性价值;LLM 层那个唯一的大未知数(前情是否稀释/带偏判定)**不进 v1 考场**——快照更小、无上下文预算问题、证伪面更窄。
- **v2:供给原文进 prompt(supply-as-context),门控实验。** 增量价值在第二档(公检法/退款类恐吓弧,judge 需读原文才能连上),走独立判据预注册,过了才进默认,不过则永远停在 v1,损失明确且有界。

### 6.6 分诊:只降级,不跳过

消息三分:命令(`新的`,及既有开通/绑定)、**确认**(纯文本 ≤20 字、无 URL、命中封闭词表:谢谢/好的/知道了/收到/嗯/哦)、查询。确认类走被动回复"收到,有可疑消息随时发我",落 `query` 打 `kind='ack'` 标签,不产生 verdict。关键纪律:**分诊永远不跳过判定,只能降级**——把真求助当客套是漏报级错误,多判一句"谢谢"是成本级错误;且确认类永远有被动回复,对老人零沉默。

### 6.7 取舍清单(每一刀切在哪)

| 选择 | 换来什么 | 牺牲什么 |
|---|---|---|
| 宁多翻、勿少翻(7 天窗/10 条上限) | 长线骗局不被切断——漏报的主战场 | token 变贵;偶尔夹带不相干旧消息 |
| 供给 v1 先进规则层,原文进 prompt 拆为 v2 门控 | 确定性内核先兑现,LLM 未知数不进 v1 考场 | v1 阶段第二档(恐吓弧)连不上,judge 读不到原文;v2 判据不过则此损失永久 |
| 翻的规则是死规则(同案 + account/url 强特征匹配),不上向量检索 | 确定性、可单测、零成本,消融文化兼容 | 无强特征共现的跨案延续供不上("还是那个平台");骗子换收款账户则跨案匹配断——已知盲区,留检索式供给实验 |
| 旧结论不给 judge 看 | 不被旧错误带偏,"担保变陈述"的时间维延伸 | judge 不知道"已警告过一次",回复没法说"再次提醒" |
| 前情不进回复文案 | "错误引用前文"这类最需要信任时刻的信任事故归零 | 回复显得没"记性",信息量打折 |
| 供给快照随 verdict 固化 | 判定可复现,断点续跑/证伪评测活得下去 | 存储与写入成本(SQLite 文本行,量级可控) |
| floor 在"前情+本条"合并集上计算 | 抓住跨消息 isolation+transfer 组合 | 供给精度不足时误抬下限的风险——由判据②把关,不过就关 |
| 整个功能带开关,评测不过就关 | 最坏情况=回到今天,不会更差 | 无,这是保险丝 |

**不做的代价**(为什么不等真实数据):知识库自己的四轮弧样本(可信度→紧迫感→情绪操纵,Fraud-R1 levelup 同构)证明最恶劣骗局的多消息形态是常态而非长尾;单条判定永远截断弧,零漏报在杀猪盘类上有结构性上限。"等回流数据"的赌注,在漏报主线上比多群案例弱得多——多群等得起因为它是功能缺口,会话边界等不起因为它是判定正确性缺口。

### 6.8 场景适配度分层(16 类,v1.3)

适配度由三个结构维度决定,不是 16 个类各一个答案:**①弧长与投喂节奏**(多天渐进弧/同日多步弧/单工件)、**②强特征跨消息稳定性**(收款账户/链接/APP 是否重复出现;骗子换号是最大敌人)、**③升级结构类型**(escalation 只认"信任→索取";"恐吓→索取"靠 isolation+transfer 下限)。

| 适配度 | 类目(taxonomy id) | 说明 |
|---|---|---|
| **最高**(多天弧+碎片投喂+信任→索取全成立) | 网络交友诱导投资(`romance_pigbutchering`)、刷单返利(`task_scam`)、虚假投资理财(`fake_investment`)、虚假兼职(`fake_parttime`) | "带你赚钱/做任务返利/导师带单"都出现在弧的早期,单条欠信号;v1 确定性内核的主战场。弱点:收款账户轮换 |
| **中高**(同日或数日多步弧) | 冒充公检法(`impersonate_police`)、冒充客服退款(`fake_refund`)、虚假贷款(`fake_loan`)、收费名目异常(`fake_fee`) | 6h 分区+供给接得住同日碎片;fee/账号特征重复命中好。弱点:恐吓类 escalation 不命中,靠 isolation+transfer 下限兜——**依赖恐吓式隔离词表(§6.9 验收项)**;judge 读原文才能连的弧要等 v2 |
| **中**(有弧但被别的因素卡住) | 保健品神药(`fake_health`)、冒充亲友借钱(`impersonate_relative`)、冒充领导老板(`impersonate_boss`)、虚假购物(`fake_shopping`) | 保健品是数周"关怀式营销"长弧、特征稳定,但常超 7 天窗口;亲友/老板借钱弧太短,供给增益小;老板类叠产品场景不匹配 |
| **低**(单工件,非目标) | 中奖免费领(`fake_prize`)、医保社保补贴(`social_insurance`)、快递理赔/补贴(`express_insurance`)、机票退改签(`ticket_refund`) | 单条链接/通知投喂,现状已够用;供给拿不到料退基线,无害 |

**价值集中度声明**:增益集中在最高两档八类,是靶向修复不是通用升级;低档类零伤害。该分布与漏报主线的落点一致。

### 6.10 判据预注册(证伪门)

**v1 判据(过了才开默认):**
1. 分层跨消息样本 Recall ≥ 单条基线,零漏报不回归;样本必须分层:信任弧(52 条会话体时序拆分导出)/恐吓弧(新增:公检法·退款类同日多步)/超窗样本(新增:测 7 天参数对长弧的切割)——不能只用信任弧自证;
2. FPR(strict) 不回归(含"误并对照");
3. 不变式断言:全样本 `level(有供给) ≥ level(无供给)`(v1 近似结构保证,仍实测);
4. 故障注入:供给组件失败 → 判定等于单条模式;
5. p95 延迟与 token 预算上限。

不过则 `supply` 默认 False,incident 分区照常上线(分区本身无判定风险)。

**v2 判据(在 v1 通过后另行预注册):** 第二档弧型 Recall 增量、前情稀释对照、锚定检查(旧结论不回流的前提下 prompt 层是否仍被带偏)、token 预算增量。

## 7. 方案遗留的开放点与赌注

1. **参数校准**:6h/7d/10 条/200 字是拍的初值,判据跑批后校准;
2. **需求假设仍是论据不是数据**:"用户会分次投喂"的依据是知识库四轮弧断言(渐进式骗局是常态),不是回流数据——观察回流路线仍是备选,若走观察,观察指标需预注册;
3. **无强特征共现的跨案延续**供不上(§6.7 已知盲区)→ 检索式供给作实验裁决;
4. **跨家族会话盲区**:骗子分别联系两名家庭成员,user 键天然切不开——本方案的真盲区,如实记录,留纠正回流兜底;
5. **案件消费端**(周报/UI)后置:分区先落库后消费。

## 8. 立项建议

- 按重构序列推进(多群模型 → 会话模型),判据预注册、先证伪再定默认(§6.10)。
- 实施切片(每步可独立上线):①DDL+分区+命令/分诊(判定零变更,supply 关着上线)→ ②转写落库 → ③v1 供给进规则层 + 恐吓隔离词表 + 快照 + 版本号(config 门控)→ ④评测跑批(分层样本)裁决 v1 默认值 → ⑤v2 原文进 prompt:预注册增量判据,过了才开 → ⑥(P2)案件消费端。
- 触发时机:建议立即立项(§6.7"不做的代价");若仍选观察回流,观察指标应预注册(同一 user 短时间内多查询率、跨查询回指词/特征复现率),避免事后找数。
- 关联遗留:过程总结 §"供应商 402"的降级丢 `rule_floor` 问题未修;会话改造会动 `Pipeline.run` 的降级分支,建议同批处理。
