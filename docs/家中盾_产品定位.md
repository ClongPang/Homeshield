## 1. 产品定位与边界

### 1.1 定位
家庭反诈联防层——身边任何人收到可疑消息,转发给"小盾"得到秒级判定与解释;高危时自动同步所在的防护群;纠正回流为评测样本。

### 1.2 成员、入口与行为模型
**防护群模型(v2.4 起:多群)**:产品只提供机制,不预设场景——建群(「开通 [群名]」)、邀请(邀请码)、查询、告警广播、信任位、退群/移除/解散、封顶护栏与命名;如何组织(家人/邻里/同事)、群叫什么、拉几个人,是用户自己的社会学。机制保证的不变式仅一条:**判定回复回到查询者;高危到达查询者所在的每一个群;信任位决定纠正的生效方式。**

- **一人可加入多个防护群**(身份与成员关系分离):同一个微信号在自家群是信任成员,在邻居群可以是普通成员——信任跟随空间,不跟随人。
- **查询永远是私人的**:回复、回执、降级提示只回到查询者自己的对话;**不存在默认群与切换操作**——没有"选错群"这回事。
- **告警广播到查询时所在的每一个群**:查询受理时记下相关群,高危判定时向这些群仍活跃的成员发提醒;一个人兼任多群只收一条。单群接收者沿用原模板,多群接收者看到相关群名;新加入的群不接收旧查询。摘要级信息跨群可见列为观察项。
- **单群成员严格零感知**:查询回执、三段式回复与原模板均不加群名;多群用户查询也不用选群。群切换器只对多群成员出现;主动发送「我的群」时可查看自己的群列表。
- **退出与解散**:成员退出/被移除后立即失去该群访问权;最后一名已绑定成员退出自动解散,创建者仍在群内且为信任成员时可主动解散。历史记录保留;重新入群仅可查看自己过去确曾收到的告警,不能查看离群期间或首次入群前的告警;群解散后家人不可查看历史。
- 成员间唯一的差异是**纠正信任位(trusted)**:一条判定每人只反馈一次,无需选群;只要其相关群中有信任位,纠正即时生效,否则进入这些群共同的待确认队列,任一相关群信任成员确认一次即可——数据质量防火墙,不是身份层级,与年龄无关。

| 成员 | 入口 | 看到什么 |
|---|---|---|
| 全体群成员 | 微信公众号对话(主):长按转发可疑消息(文字/截图),判定回复回到同一对话;控制台(链接即凭证,兜底,多群带切换器) | 大字结论("⚠️ 这是典型骗术，千万别转钱",断言消息命中已知骗术、不断言发送者身份)+ ≤3 条大白话依据 + 1 条行动建议(高危固定附"紧急可拨反诈专线96110");高危时另收一条模板消息(多群接收者带相关群名)直达详情;控制台按群看告警流、周报、纠正队列 |
| 群主/信任成员 | 控制台 | 同上 + 本群成员管理(邀请码、信任位、移除) |
| 系统 | 判定引擎 | 三层管线(《架构技术》§1.1),对成员与群数完全透明 |

**成员的真实行为循环是"得知 → 线下核实 → 事后反馈":**

1. **平时不存在**——系统对成员完全静默,没有需要主动打开的页面;
2. **得知**——高危判定发生时,微信模板消息自动送达全群(结论 + 摘要 + 详情链接);
3. **线下核实**——打电话或当面确认;这一步发生在系统之外,是真正的人类反诈动作,系统不替代它;
4. **事后反馈**——点开详情,一次点击标记"误报 / 真骗局",沉淀为纠正样本;信任位决定该反馈是否即时生效。

设计推论:**通知即入口**(落地页展示"这一条"判定的详情与反馈按钮,而不是需要主动访问的仪表盘);**反馈摩擦上限是一次点击**;**系统的成功不是让成员常来,而是让他可以永远不来——直到需要他的那一次**。控制台聚合页(队列/周报/成员)降级为兜底,不是成员的日常触点。

### 1.3 产品形态与关键取舍
- **自托管网络服务,非 App、非小程序**:安装与上架审核是长辈侧最大流失点,MVP 无原生能力刚需。
- **微信对话为主入口**:转发是长辈的原生动作,复制粘贴是最大摩擦。兜底为手机浏览器聊天页:引导"添加到主屏幕",粘贴文字/上传截图,覆盖短信等微信外内容。
- **零注册**:微信侧以 openid 映射成员,网页侧用个人链接;知情页由关注后首条自动回复承载(隐私规则见《架构技术》§3.4)。

### 1.4 服务边界(明确不做,原因)
| 不做 | 原因 |
|---|---|
| 电话渠道 | 占诈骗案 63.3%,监听不可行 + 强合规;产品只处理进入系统的文本/链接/截图 |
| 硬拦截、阻断转账 | 误杀代价不可承受;兜底是 96110 与系统级弹窗 |
| 被动监控(读聊天记录/通话) | 只处理**用户主动查证**的内容 |
| 与官方比判定权威性 | "国家反诈 AI"已上线同类能力:判定是入场券,联防才是产品 |

## 2. 功能需求与验收(MVP)

| ID | 需求 | 验收标准(done-when) |
|---|---|---|
| FR-1 | 消息接入:text / url / image(base64)归一化为 Message;微信回调按 MsgId 幂等 | 三类输入均产出结构化对象;非法输入返回 400;同一 MsgId 重试不产生重复 query/回复 |
| FR-2 | 特征抽取:规则引擎抽硬信号(金额、账号、链接、催促词、身份声称、隔离话术、收费名目异常)+ LLM 补抽语义特征;image 先经多模态 LLM 转写为文本再进抽取,失败降级提示"请粘贴文字" | 每条特征含 `{id, type, value, evidence_span, source: rule\|llm}`;对《架构技术》§6.1 样例集抽取结果可通过断言测试 |
| FR-3 | 骗术知识库:≥12 类分类学,每类 ≥3 条结构化案例(话术特征/识别点/应对建议);向量+关键词混合检索 top-2 | 人工标注类别的 top-3 检索命中率 ≥ 90% |
| FR-4 | 分级判定:safe / suspicious / dangerous,输出含 confidence(0-100,供《架构技术》§6.4 阈值扫描);理由**只能引用特征 ID**;校验器验证每个引用真实存在,失败自动重试(≤2 次) | 校验后非法引用率 = 0;重试耗尽则降级输出"需人工判断" |
| FR-5 | 回复生成:固定三段式(结论/依据/行动建议),口语化,≤150 字,长辈可读 | 格式校验(正则+长度)通过率 100%(测试集内) |
| FR-6 | 高危告警:dangerous → 查询时相关群中判定时仍活跃的成员,每人最多一条模板消息与详情链接;单群沿用原模板,多群接收者带相关未静音群名;在线控制台经 SSE 实时同步 | 新加入的群不接收旧查询;落地页展示该条判定详情并提供一键反馈(误报 / 真骗局);alert 按"群×接收成员关系"留记录,微信推送按用户去重与按群静音 |
| FR-7 | 纠正回流:每人对每条判定只需一次点击,系统确定有权反馈群;任一相关群信任成员的纠正即时生效,普通成员纠正进入共同的 pending 队列,任一相关群信任成员确认一次即可;纠正样本留存于库 | 状态机测试通过(《架构技术》§3.3);pending 纠正在确认前不进入统计;点击反馈无需选群 |
| FR-11 | 多群机制:一人可加入多个防护群(身份/成员关系分离);「开通 [群名]」建群、「我的群」列表、「退出 群名」退群、创建者「解散 群名」、信任成员移除成员;控制台群切换器;单群成员零感知 | 查询不选群;多群高危推送覆盖查询时相关且判定时活跃的群,按用户去重;退群/解散即撤销群访问、留历史审计;单群模板与三段式结构沿用 v2.3,未通知时纠正原有错误文案 |
| FR-8 | 按群周报:查询数、高危数、误报数、纠正数 | 控制台选真实群查看;查询在查询时所在各群分别计数,不显示虚假的跨群合计;pending 不计入纠正数 |
| FR-9 | 评测脚本:数据集加载、指标计算、消融矩阵、阈值扫描、生成 `docs/reports/report.md` | 一条命令复现全部数字 |
| FR-10 | Mock/LLM 双模式:无 API key 时规则判定跑通全链路 | `MODE=mock` 下全部测试通过 |

**非功能**:Python 3.12(uv 管理);单机部署;SQLite 存储;延迟为设计参考值而非验收指标(《架构技术》§1.1)。

## 4. 决策记录(仅保留影响设计的)

### 4.1 已采纳
| # | 决策 | 依据 | 来源 |
|---|---|---|---|
| 1 | 放弃电话渠道,只做消息层 | 电话占诈骗案 63.3% | 公安部统计,https://www.miluo.gov.cn |
| 2 | 第一用户是年轻人自己,长辈是高损失群体 | 受害者 18-40 岁占 62.1%(公安部 2023) | https://www.gxust.edu.cn |
| 3 | 判定不做差异化,主打家庭联防 | "国家反诈 AI"App 2026-09 上线(LLM 问答+多模态识诈) | 人民网,http://society.people.com.cn |
| 4 | 评测集设 AI 生成话术子层 | 检测器对 LLM 生成话术性能显著下降(Frontiers 2026) | https://www.frontiersin.org |
| 5 | 演示用测试号;生产用认证服务号;"回 success + 客服接口异步"组合 | 微信平台规则(2026-09 核验,技术细节见《架构技术》§2) | — |
| 6 | 防护群模型:全员平权收推送/可查询;elder/adult 角色退役为纠正信任位(trusted),由群内信任成员管理 | 联防的产品语义是"群"而非"家庭层级";告警受众不该由年龄决定;纠正信任保留为数据质量防火墙,防诚实误标污染回流数据 | 产品讨论 2026-09-26 |

### 4.2 已否决(微信接入备选)
| 方案 | 否决原因 |
|---|---|
| 个人订阅号 | 个人无法微信认证,无客服接口/模板消息 |
| 企微微信客服 | 需企业验证;48h 窗口卡死向子女的主动告警 |
| 企微智能机器人 Bot API | 未验证企业可用,且进不了含普通微信用户的外部群 |
| 家庭群机器人 | 无官方 API,协议方案有封号风险 |

### 4.3 观察项(2026-09 调研)
微信已通过 ClawBot/iLink 协议(ilinkai.weixin.qq.com)官方开放个人微信侧 Bot 通道:扫码登录、免企业认证(OpenClaw 的 openclaw-weixin 插件由腾讯微信团队维护);当前仅支持单聊+媒体,群聊未开放,生态尚新。"长辈与 bot 单聊"正是主入口形态——D4 后评估以 iLink 替代公众号作为长辈主入口;家庭群机器人仍待群聊能力开放。
