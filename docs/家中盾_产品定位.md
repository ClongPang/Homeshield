## 1. 产品定位与边界

### 1.1 定位
家庭反诈联防层——身边任何人收到可疑消息,转发给"小盾"得到秒级判定与解释;每次查证自动同步给联防者;纠正回流为评测样本。

### 1.2 成员、入口与行为模型
**联防关系模型(v2.9 起,取代防护群)**:产品只提供机制,不预设场景——联防是一条**双方同意的单向关系**:发「邀请」者成为**联防者**(接收对方的查询提醒、参与对方判定的纠正投票),持码「绑定」者成为**被联防者**(查证同步给对方);要互相守护,交换邀请、各建一条。和谁建、叫什么称呼、护几个人,是用户自己的社会学。机制保证的不变式三条:**判定回复回到查询者,零关系也可裸查询;查询提醒沿查询受理时活跃、判定时仍活跃的联防关系扇出,不按判定等级过滤(决策 #10);方向即角色——联防者是该被联防者判定的信任投票者,被联防者可提交普通反馈。**

- **关系是唯一协同原语,不存在群容器**:没有建群、群主、信任位管理与解散;生命周期只有建立(邀请码)与解除(任一方单方立即生效,不通知对方)。解除后立即失权:新告警不再同步,历史提醒不可再看;重建同方向创建全新关系,不复活旧行。
- **查询永远是私人的,且不设门槛**:回复、回执、降级提示只回到查询者自己的对话;没有任何关系的裸用户同样获得完整判定——联防只在其上增加查询同步与纠正投票,不把建关系设为使用前提。
- **提醒沿关系扇出,不由判定等级把关**:查询受理时记下当时活跃的"被联防"关系,判定完成时(不论等级)向仍活跃关系的联防者各发一条提醒(带被联防者称呼与判定结论);每条关系至多一条,天然无重复;受理后、判定前解除的关系不收本条。按关系静音只静提醒,历史与实时流保留。扇出由查询事件触发而非判定等级:用户转发查证本身就说明起了疑心,判定必有漏报,漏报时不能让家人被系统挡在外面;注意力管理(忽略/静音)是联防者自己的选择,机制只负责忠实送达。
- **纠正由联防者多数票确认**:查询者可提交普通反馈,不计票;本条判定对应的合格联防者各投一票,同一标签严格超过固定人数的一半才成为已核实结果。1 人需 1 票,2 人需 2 票,3 人需 2 票;平票、无人投票及零联防者均不能自证。七天无多数记为「未达共识」,反馈仍保留,不进入可信回流。联防者身份只对其所联防的人生效,不使自己的查询自动获得信任票。
- **命令四件套**:`邀请 [称呼]` / `绑定 <码>` / `我的联防` / `解除 <称呼>`;旧群命令(开通/我的群/退出/解散)退役,回复一次性迁移提示。每用户活跃关系总数受 `MAX_RELATIONS` 护栏,服务级不设上限。

| 角色 | 入口 | 看到什么 |
|---|---|---|
| 全体用户 | 微信公众号对话(主):长按转发可疑消息(文字/截图),判定回复回到同一对话;控制台(链接即凭证,兜底) | 大字结论("⚠️ 这是典型骗术，千万别转钱",断言消息命中已知骗术、不断言发送者身份)+ ≤3 条大白话依据 + 1 条行动建议(高危固定附"紧急可拨反诈专线96110");控制台看「我的查询」(判定历史与普通反馈)与关系管理;零关系仍可查证 |
| 联防者 | 控制台/查询提醒推送 | 同上 + 「我收到的提醒」(被联防者的查询流)、待我投票队列、关系管理(邀请、撤销未用码、称呼、静音、解除) |
| 系统 | 判定引擎 | 三层管线(《架构技术》§1.1),对用户与关系数完全透明 |

**成员的真实行为循环是"得知 → 线下核实 → 事后反馈":**

1. **平时不存在**——系统对成员完全静默,没有需要主动打开的页面;
2. **得知**——判定完成时,查询提醒自动送达各联防者(判定结论 + 摘要 + 详情链接);
3. **线下核实**——打电话或当面确认;这一步发生在系统之外,是真正的人类反诈动作,系统不替代它;
4. **事后反馈**——点开详情,一次点击标记"误报 / 真骗局";同一判定的联防者票数过半后,结果才成为已核实纠正样本。

设计推论:**通知即入口**(落地页展示"这一条"判定的详情与反馈按钮,而不是需要主动访问的仪表盘);**反馈摩擦上限是一次点击**;**系统的成功不是让成员常来,而是让他可以永远不来——直到需要他的那一次**。控制台聚合页(投票队列/关系)降级为兜底,不是成员的日常触点。

### 1.3 产品形态与关键取舍
- **自托管网络服务,非 App、非小程序**:安装与上架审核是长辈侧最大流失点,MVP 无原生能力刚需。
- **微信对话为主入口**:转发是长辈的原生动作,复制粘贴是最大摩擦。兜底为手机浏览器聊天页:引导"添加到主屏幕",粘贴文字/上传截图,覆盖短信等微信外内容。
- **零注册**:微信侧首次发消息按 openid 建个人身份,不要求先建联防关系;网页侧用个人链接,可回复「我的联防」重新取得,不开放匿名网页查询。关注后的欢迎回复说明查询同步与低风险纠正时的原文共享范围(隐私规则见《架构技术》§3.4)。

### 1.4 服务边界(明确不做,原因)
| 不做 | 原因 |
|---|---|
| 电话渠道 | 占诈骗案 63.3%,监听不可行 + 强合规;产品只处理进入系统的文本/链接/截图 |
| 硬拦截、阻断转账 | 误杀代价不可承受;兜底是 96110 与系统级弹窗 |
| 被动监控(读聊天记录/通话) | 只处理**用户主动查证**的内容 |
| 与官方比判定权威性 | "国家反诈 AI"已上线同类能力:判定是入场券,联防才是产品 |

## 2. 功能需求与验收(MVP)

| ID | 需求 | 验收标准(done-when) |
|---|---|---|
| FR-1 | 消息接入:text / url / image(base64)归一化为 Message;微信回调按 MsgId 幂等 | 三类输入均产出结构化对象;非法输入返回 400;同一 MsgId 重试不产生重复 query/回复 |
| FR-2 | 特征抽取:规则引擎抽硬信号(金额、账号、链接、催促词、身份声称、隔离话术、收费名目异常)+ LLM 补抽语义特征;image 先经多模态 LLM 转写为文本再进抽取,失败降级提示"请粘贴文字" | 每条特征含 `{id, type, value, evidence_span, source: rule\|llm}`;对《架构技术》§6.1 样例集抽取结果可通过断言测试 |
| FR-3 | 骗术知识库:≥12 类分类学,每类 ≥3 条结构化案例(话术特征/识别点/应对建议);向量+关键词混合检索 top-2 | 人工标注类别的 top-3 检索命中率 ≥ 90% |
| FR-4 | 分级判定:safe / suspicious / dangerous,输出含 confidence(0-100,供《架构技术》§6.4 阈值扫描);理由**只能引用特征 ID**;校验器验证每个引用真实存在,失败自动重试(≤2 次) | 校验后非法引用率 = 0;重试耗尽则降级输出"需人工判断" |
| FR-5 | 回复生成:固定三段式(结论/依据/行动建议),口语化,≤150 字,长辈可读 | 格式校验(正则+长度)通过率 100%(测试集内) |
| FR-6 | 查询提醒:判定完成(不论等级)→ 查询受理时活跃、判定时仍活跃的联防关系,每条关系至多一条提醒与详情链接,带被联防者称呼与判定结论(dangerous 高危预警 / suspicious 留意 / safe 未发现典型骗术特征);按关系静音只静提醒;在线控制台经 SSE 实时同步;联防者可自助开通应用消息推送(插件关注前置 + OAuth/手机号绑定 + 测试消息确认闭环,通道状态四态如实呈现),未绑定/异常时如实回落客服会话 | 受理后判定前解除的关系不收本条;解除后新提醒不再同步、历史提醒失权;裸查询无提醒但判定完整;只把已生成的提醒告知查询者,不声称应用消息已送达;扇出由查询事件触发,判定等级只影响提醒措辞 |
| FR-7 | 纠正回流:查询者可提交一次普通反馈;同一判定的合格联防者一人一票,某标签达到 `floor(N/2)+1` 才成为已核实纠正,N 在纠正开启时固定;七天无多数为「未达共识」,零联防者的反馈不自证 | 只有已核实标签进入可信回流;重复投票不加票/不改票;低风险判定仅在查询者主动反馈后向合格联防者展示原文,绑定时说明该共享范围 |
| FR-11 | 联防关系机制:单向关系为原语,「邀请 [称呼]」发码(邀请者=联防者)、「绑定 <码>」接受(绑定者=被联防者)、「我的联防」两段列表、「解除 <称呼/#关系ID>」单方解除;控制台关系页与「我收到的提醒 / 我的查询」两视图;零关系裸查询放行 | 一人可同时与多人建多条关系,双向=两条单向;解除立即失权且不通知对方;重建为全新关系;未用邀请码可撤销;裸查询走完整判定管线;MAX_RELATIONS 护栏生效 |
| FR-9 | 评测脚本:数据集加载、指标计算、消融矩阵、阈值扫描、生成 `docs/reports/report.md` | 一条命令复现全部数字 |
| FR-10 | Mock/LLM 双模式:无 API key 时规则判定跑通全链路 | `MODE=mock` 下全部测试通过 |

**非功能**:Python 3.12(uv 管理);单机部署;在线服务运行数据使用 Postgres 16,SQLite 仅用于离线 `kbbuild`;延迟为设计参考值而非验收指标(《架构技术》§1.1)。

| 10 | 查询级同步:提醒扇出由查询事件触发,不按判定等级过滤;等级只体现为提醒措辞(dangerous 高危预警、suspicious 留意核实、safe 不带警示符);知情文案一句话说清机制("你的每次查证都会提醒联防你的人"),不做分级披露与防御性措辞 | 查询本身就说明用户起了疑心,判定等级只是机器参考,不该反过来决定家人知不知情;判定必有漏报,漏报时家人被系统挡在外面是静默失效,事后无法追责也无法补救;漏报不可逆、打扰可逆,方向必须是宁可多报;注意力管理(忽略/静音)是联防者自己的选择,机制只负责忠实送达;知情同意的实质在关系是双方自愿建立的,一句话说清胜过免责堆砌 | 产品讨论 2026-09-28 |
