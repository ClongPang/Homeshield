# 家中盾(Homeshield)—— 判定模型设计教训

> 版本:v1.2 | 2026-09-26 | 状态:**模型定稿;知识库补齐与重构二/三/五已落地,证伪跑批执行中**(落地状态见 §5)
> 读者:接手判定管线与知识库的人。本文记录一次设计复盘:错误是什么、为什么错、修正后的模型是什么。
> 姊妹篇:《家中盾_产品定位》(做什么)、《家中盾_架构技术》(怎么建)。本文是两者的**设计依据层**——重构二~五的正确性都以此为前提。

## 1. 背景:这次复盘是怎么触发的

调研 Fraud-R1(Findings of ACL 2025,基准)与 FraudShield(WWW 2026,防御)后,曾提出"两层知识模型":**机制卡**(封闭小集合,负责识别)+ **类型卡**(开放集合,负责命名与建议),并配了 10 张机制卡的草案,每张带"正常对照"列以图防误报。

用户质询点破了一个被忽略的结构问题:"不管怎样的骗局,总会有相似的欺诈模式本质,不然永远都是特例识别"。重审后发现:**草案方向正确,但内含三处错误**——若不修正,将顺着重构路线(内联标注→抽取主通道→会话化)把错误固化进知识库和评测集,且事后难以拆除。

## 2. 三个错误与修正

### 错误一:单卡"正常对照"承诺了它做不到的事

**错误**:声称每张机制卡配"正常对照"(如"真促销也有紧迫感")即可防误报。

**为什么错**:误报不来自单机制,而来自**多机制共现的正常消息**——真家人急事借钱 = 身份(亲人)+情感+紧迫+资金动作,四机制全中但正常;真催缴 = 紧迫+资金动作;真理赔 = 可疑信息+敏感索求。组合级的正常情形是无穷枚举,单卡对照在组合层面完全失效——这等于把"特例识别"从类型层原样搬到机制层,问题只是换了楼层。

**修正**:把 10 个机制向上收敛为**三个功能**(§3.1),判别轴不是机制罗列,而是**核实抑制**:正常消息可以包含索取与信任替代,但不会阻止你核实;骗局的定义性结构是"**索取 + 阻止你核实**"。真家人借钱没有核实抑制,正确判定是 suspicious(输出动作即"打电话核实本人"),而不是 dangerous,也不是 safe。这也解释了为什么所有反诈口诀的落点都是"多核实"——核实是唯一通用解药。

### 错误二:机制组合差点被写成第二个规则引擎

**错误**:机制卡草案带"组合规则",顺着走就是 `if 紧迫 ∧ 资金 then …` 的打分表。

**为什么错**:那是在用更多步骤重建我们要替换掉的脆弱规则引擎。词表组合打分正是 LLM 判定要替代的东西;机制层的价值在于**表示**(抽取什么、标注什么、引用什么),不在**判定**。

**修正**:钉死边界——机制是表示层;确定性规则只保留规则下限一条(它是分级语义的确定性子集);其余分级全部是 LLM 在"机制标注后的原文"上的判断,受分级语义(§3.2)约束。机制卡里不写 if-then,只写语义。

### 错误三:评测是单侧的,后续所有数字都会失真

**错误**:评测资产只有 scam 侧(32 条候选 + 128 条退化集,全部正样本)。

**为什么错**:FraudShield 的实验只需要 scam 侧(DSR),其实用指标 MMLU 不含欺诈干扰——**它没有 benign-hard 对照需求,我们有,而且 FPR 是第一指标**。只拿单侧集验证重构,完全可能出现"Recall 涨了、FPR 也涨了"而评测不可见:内联标注天然有把 judge 往 dangerous 方向锚的风险(把锚定误报从检索层搬进了标注层),没有对照集就发现不了。

**修正**:对照组必须是**考题**,不是卡片上的一行字。benign-hard 对照集(§4)与 scam 侧同步建设,没有它,任何 Recall 数字不得采信。

### 附:一处证据引用降级

FraudShield 的 +23.88%(Assistant)/+47.17%(Role-play)来自:英文语料、LLM 生成文本、LLM 当受害者的设定。外推到"中文口语长辈消息 + 给人做分级判定"是**假设,不是结论**。故重构二(内联标注)带证伪条件合入(§4)。

## 3. 修正后的判定模型

### 3.1 三功能 × 十一机制(封闭集合,版本化)

任何骗局 = 若干机制的组合;机制的表面实体(ETC、医保、AI 换脸)会变,功能不变。

> 落地注记:注册表实现于 `src/homeshield/core/knowledge/mechanics.py`(MECHANICS_VERSION=1.0),
> 与 features.py 各规则词表的子集一致性由 `tests/test_mechanics.py` 保证;
> 机制卡内容经 git 评审修订,`marker_candidate` 审核队列留给语料挖掘出的候选(重构三)——
> 理论层与挖掘层的闸门不同,不混用。

| 功能 | 机制 | 本质 | 典型话术 |
|---|---|---|---|
| **索取**(要什么) | sensitive 敏感索求 | 直接拿走凭证 | 验证码/密码/人脸/银行卡号 |
| | money 资金动作 | 完成收割 | 转账/垫付/先交费/刷流水 |
| | control 控制权索取 | 拿走操作能力 | 屏幕共享/远程控制/代操作 |
| **信任替代**(为什么信) | identity 身份冒充 | 替代对身份的核实 | 公检法/客服/领导/儿女 |
| | bait 利益诱饵 | 替代对回报的核实 | 高收益/中奖/低价/返利 |
| | fear 恐惧威胁 | 替代对后果的核实 | 涉案/冻结/逾期后果 |
| | emotion 情感操纵 | 替代对动机的核实 | 恋情/亲情/卖惨/身份认同 |
| **核实抑制**(为什么不能核实) | urgency 紧迫施压 | 时间抑制 | 最后一天/限时/马上 |
| | isolation 隔离封口 | 社会纠错抑制 | 别告诉家人/保密 |
| | antiverify 阻断核实 | 官方纠错抑制 | 别打官方电话/官方查不到 |
| | escape 渠道逃逸 | 平台纠错抑制 | 加私人微信/下陌生App/脱离平台 |

机制集**理论先行**(从三功能推导,不从语料聚类——聚类只负责给机制填充证据与权重),封闭、带版本号;新机制入集需走审核,防止机制集本身变成另一种特例枚举。

### 3.2 分级语义(判定引擎的唯一确定性约束)

- **dangerous** ⟸ 索取(资金/敏感凭证/控制权) ∧ 核实抑制显著(紧迫+隔离 / antiverify / escape);
- **suspicious** ⟸ 有索取或不可核实的强声称,但无核实抑制 → 回复的"行动建议"就是**给出核实路径**;
- **safe** ⟸ 无索取 ∧ 无核实抑制。

规则下限 `isolation+money → dangerous` 是该语义的确定性子集,保留不变;每张机制卡附**核实路径**(该机制的解药:identity→官方渠道回拨,bait→官方 App 查证,escape→回到平台内……),供回复生成引用。

### 3.3 两层知识模型(职责重申)

- **机制层**(本模型):封闭集,负责识别与定级,泛化的来源;
- **类型层**(cases.json 等):开放集,机制组合的**建议查找表**与家人沟通的命名单位;类型缺失 = 建议不够具体,**不等于漏检**;类型判定是 LLM 参考"机制+案例"的判断,不是查表(如"杀猪盘"是跨天过程标签,单条消息原则上看不见);允许输出"未收录类型"。

## 4. 对评测的硬性要求

1. **双侧集**:scam 侧(已有 Fraud-R1 候选,待过筛)与 **benign-hard 对照集**同步。对照集分两层——
   - **Tier 1 模板改编层**(已落地:`data/samples/benign_hard.jsonl` 14 条):从公开的官方通知体裁(银行账单/验证码/航班退改/医保缴费/催缴/会员营销/ETC/理赔进度等)逐条改编,`source=adapted:*`,逐条标注机制共现;测的是"**官方体裁 + 机制共现**"的硬度;
   - **Tier 2 真实收集层**(验收线,见 §4.1):关系与语境类硬对照(真家人借钱、惊喜保密、真理赔对话)只能来自真实消息,禁止改编代替。
2. **重构二+五的证伪条件**:双侧集上 **Recall 上升且 FPR(strict) 不升**,方可合入;FPR 上升 → 回退或加约束并重扫阈值。
3. 所有变更沿用《架构技术》§6 纪律:每次变更附复测证据;合成数据只用于 CI 与冷启动;质量收敛唯一标准是真实使用。

### 4.1 benign-hard Tier 2 收集协议

| 类目 | 配额 | 来源要求 | 脱敏规则 |
|---|---|---|---|
| 真家人借钱聊天(含"保密"变体) | ≥5 | 家庭成员真实聊天记录,提交人确认为真 | 去姓名/昵称/账号;金额可改写保位数级 |
| 惊喜策划式"保密"(生日/仪式) | ≥3 | 同上 | 同上 |
| 真快递理赔/退款完成对话 | ≥3 | 家人真实经历截图或回忆复述,标明"复述" | 去订单号/电话/链接域名 |
| 真催缴/官方通知实拍 | ≥5 | 家里真实收到的短信/票据照片转写 | 去户名/尾号,保留金额与期限 |
| 长辈群真实转发(正常内容) | ≥5 | 家庭群/长辈群真实消息 | 去转发人信息 |

每条入库字段与 Tier 1 相同(`mechanics` 标注必填),`source=correction:<版本>` 或 `adapted:<真实出处>`,经 adult 确认后入库;**覆盖验收以 `src/homeshield/eval/contrast.py` 报告为准**:control 与 sensitive 的 dangerous 区(索取∧核实抑制)对照缺口清零前,相关机制上的 FPR 结论不得采信。

## 5. 落地顺序与不做清单

1. ✅ **机制理论定稿 + 机制卡注册表**:11 张卡落地于 `src/homeshield/core/knowledge/mechanics.py`(定义/种子词表/核实路径),种子词语料支撑度报告:`uv run homeshield-kbcli mechanics-report`;
2. ✅ **对照集 v0(Tier 1)+ 验收工具**:14 条模板改编层入库,机制覆盖检查器 `src/homeshield/eval/contrast.py`;**Tier 2 真实收集是当前关键路径**(§4.1 协议)。验收发现:种子词在 Fraud-R1 语料中 40 个零支撑,其中 antiverify 全部 8 词、isolation 5/7 零支撑——**体裁偏差的实证**:这类话术出现在多轮对话后段(受害者起疑后),首轮单条语料天然不含;结论:①零支撑词不删(运行时权威在 features.py,真实渠道有效);②"阻断核实/隔离"机制的检出**依赖重构四的会话化**,单条消息判定对此类信号先天失明;
3. ✅ **重构二+五 代码落地**(`src/homeshield/core/annotate.py` + `JudgeInput.annotated_text/graded_semantics` + `LLMJudge` 提示扩展 + 消融 D/E):机制内联标注 `<机制名>证据</机制名>`、分级语义进判定提示、MockJudge 不受影响;**证伪条件待双侧集就绪后执行**(消融矩阵已含 D/E,`product_default` 保持 C,证伪通过才翻转默认);
3b. ✅ **知识库补齐(2026-09-26)**:分类学 12→16 类(新增中奖免费领/医保社保补贴/机票退改签/保健品神药,均为长辈高发);案例 12→50 条(每类 ≥3 子模式);kbbuild 映射 phishing 内容二次分流 + BEC/教培退费标签路由修正(可映射 834→926/1,070,缺口 236→144);**修复检索 query 缺陷**(原实现仅拼特征值,弱特征消息如"只有卡号"必然检索失效,改为特征值+原文片段)。**验收教训**:代理集硬凑 90% 即过拟合——FR-3 拆双门限:Gate A 规格线 90% 作用于自有分布 smoke 集(通过),Gate B 地板 55% 仅为代理集回归护栏,境外体裁子集(美式服务钓鱼等,约 1/3)缺口如实挂账,由 EMBED 通道与真实回流解决;
3c. ✅ **重构三 代码落地**:`supplement_llm` 按机制封闭集合出证据与置信分(`Feature.confidence`,机制外/空值丢弃),与离线挖掘共用 `MECHANIC_EXTRACTION_PROMPT` 保证同源;annotate 支持机制 id 直标;MockJudge 机制权重对齐;
3d. ✅ **双侧集 v0(55 条)+ LLM 证伪跑批(C/D/E)——完成,判据通过,默认已翻转**(2026-09-26):E 对 C Recall 持平 0.758、FPR 0.045→0(消除唯一一起 dangerous 级误报)、FPR(strict) 持平 0.182 → **通过,`product_default` 翻转为 E**,消融 C 显式固定为旧默认保持基线可比;D 单独不通过(FPR(strict) 0.227——分级语义使 judge 对边缘档更保守,被内联标注对冲,二者配套)。国内 smoke 子集 Recall C 0.833 → E 1.000;代理子集 0.741 → 0.704(境外体裁,见 Gate B)。过程修复三个工程缺陷(embed 单批 ≤25 分批/JSON 响应形态归一/客户端 60s 超时),并因一次 402 中断催生逐样本断点续跑(`--checkpoint`)。完整数字:`docs/reports/falsification_report.md`(重算自 165 行 checkpoint)。**口径声明:冷启动/合成改编数据,仅证明架构选择更优,非产品质量**;
4. 挖掘执行(`fr-mine` 走 `marker_candidate` 队列)待证伪后启动;
5. ✅ **重构四 会话一等公民(2026-09-26 落地)**:`Conversation{turns[]}` 进管线——单条消息=1 轮(对外接口不变),聊天截图按"发言人:"逐行分轮;特征逐轮归属(`Feature.turn`)、**跨轮升级特征**(信任替代先于索取 → `escalation`)入规则层;judge 按轮次渲染审读并获多轮欺诈提示;评测侧 `Sample.turns` + 会话体导出(`fraud_r1_conversations.jsonl`,52 条=13 类×4,Fraud-R1 levelup 同构)。会话体 C vs E 跑批判据(预注册):全正样本集,Recall_E ≥ Recall_C。至此路线图重构二/三/四/五全部落地;antiverify/后段话术的检出通道(跨轮)打通。

**不做**:不写机制组合评分引擎;不等类型卡齐全才上线判定;不拿单侧数字宣布改进;不把"正常对照"写成卡片文字(写成考题);不从语料聚类推导机制集。

## 6. 一句话教训

**识别靠机制(骗术为什么有效),定级靠核实结构(骗局是什么:未经验证的索取 + 核实抑制)——两者不能混。表示层与判定引擎的边界、对照组作为考题而非注释、外部证据必须携带适用域与证伪条件,是本次三条可复用的工程教训。**
